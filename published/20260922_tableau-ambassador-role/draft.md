## Keynoteで語られたメッセージ

Keynoteを一言でまとめると、TrustとSpeedで、Data-driven企業からAgentic Analytics企業へ移行しよう、という話だったと理解しています。その中身が、3つのステップと、それに紐づく4つの製品・新機能でした。

### Keynoteの中身

上記の「3つのステップ」とは、以下の通りです。

- 組織の全員をBuilderにする（Tableau Studio / Tableau Data Appsの話）
- Intelligenceの側から人のところへ来させる（Proactive Intelligenceの話）
- 信頼できる基盤の上に組織の意味と文脈を載せる（Tableau Knowledgeの話）

![3ステップと製品のまとめスライド](images/keynote-playbook-summary.jpg)

**Tableau Studio**

チャットと従来型の編集画面を行き来しながら、Tableau Agentと一緒にデータ分析を行い、そしてチャートを作る体験を提供するアプリのようです。AIと人間の協業を前提に設計された分析環境に見えました。これは従来のようなTableau AgentがTableau製品の上に乗っただけのような形ではなく、AI-nativeなBIを目指している印象を受けました。

（詳細は後述し、まずは紹介に留めます）

[Tableau Studioの紹介パート（開始から10分ほどから）](https://www.youtube.com/watch?v=Gg37k9tM7vo&t=613s)

![Tableau Agentとのチャット画面](images/keynote-tableau-studio-2.jpg "Tableau Studioのチャット画面でデータ分析をする様子。動画で見る方が分かりやすいです。")

![編集キャンバスとTableau Agentの並列表示](images/keynote-tableau-studio-3.jpg "チャットに表示されたVizを、Tableauの見慣れたUIで編集する様子。")

**Tableau Data Apps**

ClaudeやChatGPTの中でTableauのデータを使ったアプリを作り、それをTableau（実際にはTableau Next?）へパブリッシュできる機能のようです。

TableauのVizを作る機能ではなく、Webアプリ自体を作ってそのままTableau（Tableau Next?）で共有するための機能のように見えました。

Tableauユーザー的には、作ったTableau ExtensionsをそのままTableau上で公開できるようなイメージになるのかなと。ちょっと続報と詳細を待ちたいですね。

自分は最初、既存のTableau MCPやTableau系のPluginを総称してTableau Data Appsと呼んでいると誤解していました。Keynote前の9/14に[ChatGPT向けPluginが出た](https://x.com/tableaujapan/status/2099438109158998353)ニュースが印象的だったので、そういう話という先入観で見てしまった...

**Proactive Intelligence**

既存のデータアラートの上にエージェントが常駐し、変化を見つけてSlack / Teams / ChatGPT / Claudeなど、あなたが良く使うツールへ届ける、という世界観のようです。

発表の中にあった以下の言い回しが印象的でした。

> What if instead of looking for an insight, intelligence found you at the right moment in your flow of work?（インサイトを探しに行く代わりに、仕事の流れの中のちょうどいい瞬間に、Intelligenceの方からあなたを見つけに来たらどうだろう？）

[Proactive Intelligenceの紹介パート（開始から23分30秒から）](https://youtu.be/Gg37k9tM7vo?si=yCIWMJkJueDI7MWk&t=1410)

**Tableau Knowledge**

組織にとって唯一の、信頼できるナレッジの基盤、という位置づけでした。

セマンティックモデルやパブリッシュ済みデータソース、ドキュメントや用語集を読んで、ナレッジグラフを自動で作ります。

構築されたナレッジがどれだけ健全かはHealth Scoreとして示され、指標の定義の衝突や、いつの間にか定義が変わった指標を検知して、修正案まで出してくれるようです。

リッチなTableau Catalogと何が違うのかと思って見ていたのですが、修正対象を自動で検知して直す提案まで組み込みで出てくる体験は面白そうでした。

### Tableauの世界観がどう変わっていくのか

自分が好きだったのは1つめのBuilderの話で、その次が3つめの基盤の話でした。

今、データを使って何かを作る、可視化する、分析する、という作業は、TableauのCreator / Explorer / Viewerというライセンスの区分には全然閉じていませんよね。ライセンスに関わらず、Tableauにあるデータもないデータも、自分のビジネス上の行動や意思決定のために生成AIと協業して、分析やレポートを作ることは、もう普通にあると思っています（MCPとかSkillsとかPluginsとかの仕組みに感謝）。

全員がBuilderになる、というのは、そういう世界観の話として受け取りました。

一方でそれを実現するには、全員がランダムなデータを使う世界ではなく、信頼できるセマンティクス・コンテキスト・データを持つプラットフォームに繋がって、その資産を使えている必要があります。1つめと3つめは、自分の中では対になっています。

主題そのものは、ある意味当たり前の話だと受け取りました。AIを使っている側からすれば「まぁこの方向に行くよね」という帰結です。

![ライセンス区分に閉じず、誰もが生成AIと協業して自分の行動や意思決定のための分析やレポートを作るBuilderの層を、信頼できる基盤（セマンティクス・コンテキスト・データ）が下から支える図](images/builder-and-foundation.png)

一方で、結構大きめの世界観の変更を伝えているように見えたのは製品の側、特にTableau Studioでした。

Keynoteの言葉を借りると、Tableau Studioはゼロから作り直してデスクトップの動き方を考え直した、再構想されたTableauです。つまり既存のTableauにAI機能が足されたのではなく、Tableau Desktopというアプリが提供する体験そのものが、可視化を作るためのツールから、生成AIと協業しながらデータ分析をするためのツールへ変わっています。その時点で「Tableauとは何か」という世界観が大きく動いたと思っています。

では、Tableauのアプリの外にいる時はどうか。一日をClaudeやChatGPTで始める層（自分含む）の話です。Keynoteではこの側をheadless analyticsという言葉で置いていて、Tableauのナレッジやコンテキスト、セマンティクスを、SlackやTeams、ChatGPTといった普段いる場所から使う、という位置づけでした（開始から7分ほど）。

![Headless Analyticsのスライド](images/keynote-headless-analytics.png "Tableauのエンジン群の上にHeadless Analyticsの帯があり、普段のAIツールのアイコンが並ぶ。右端にはMCPs / APIs / Skillsも（出典: 同、約7分）")

Keynoteの中では一言でしたが、自分が実体として思い浮かべるのはTableau MCPと、ChatGPTやCodex向けに出てきたPluginの方です。[AI案・要確認: 著者が普段 Tableau MCP／Plugin をどう使っているか、一言あれば入れる]

作る場所がTableau Studioでも普段のAIツールでも、同じ信頼できる基盤につながって、その資産を使う。ユーザーをTableau Studioに閉じ込めない、という世界観です。

一言でいうと、「Tableauの上にAI」から「AIを中心に据えたTableau」への反転かなと。これまではTableauという製品の上にTableau Agentのような機能が乗る形でした。これからはAIとの協業を中心に置いた上で、Tableauのアプリの中（Tableau Studio）でも普段のAIツールの中（Tableau MCP / Plugin）でも同じ信頼基盤につながる形に、体験を作り直そうとしているように見えます。

![「Tableauの上にAI」から「AIを中心に据えたTableau」への反転。生成AIとの協業を中心に、Tableau Studio と、Tableau MCP / Plugin 経由の普段のAIツールが同じ信頼できる基盤の上に並ぶ](images/ai-centered-tableau.png)

ということで、Keynoteを自分なりに総括すると、Tableauは可視化を作るツールから、生成AIと協業してデータ分析をするためのツールへ変わろうとしている、というものでした。ライセンスに関わらず全員がBuilderになり、その足元に信頼できる基盤があり、Intelligenceの側から人のところへ来る。その3つが揃った姿を、Tableauが自分の製品で示してきたのが今回のKeynoteだったと受け取っています。

## なぜ今年、Tableau Ambassadorとして活動するのか

後半は、今年からTableau Ambassadorとして活動させていただくにあたって考えていることです。一言でいうと、生成AIをもっと発信するTableauユーザーが日本にいてもいいよね、という話になります。

### 肩書なしでやってきたこと

自分はこれまで、Tableau Ambassadorという肩書を持たずにブログや登壇をしてきました。持たなかったというより、自分の中のアンバサダー像と、自分がブログでやりたいことが噛み合っていなかった、というのが近いです。

公式のページでは、Tableau Ambassadorはこう説明されています。

> Tableau Ambassadors teach and share while fostering a positive and supportive space within the community.

- 参考：[Tableau Ambassadors](https://www.tableau.com/community/community-leaders/ambassadors)

自分の中のアンバサダー像もこれに近くて、Tableauという製品の魅力や可視化のパワーをTableauコミュニティに伝え広めて、コミュニティを運営する人でした。大事な役割ですし、自分以外にもできる人がいる領域だと思っていました。

一方で、肩書が無くてもブログや登壇で伝え広めることはできていました。そして自分がブログでやりたいこととは、マッチしていないと思っていた、というのが実際のところです（細かい経緯は割愛します）。

### 今年、考えを変えたところ

考えが動いたのは5月のTC26でした。Visionary（Tableauコミュニティリーダーたち）が生成AIの流れを受けて、自分の役割や仕事、Tableauとの協業の仕方や向き合い方を変えようと頑張っている発表を見て、あの構図は5月の記事にも書きました。

- 参考：[TC26を浴びて、「Architect」というキーワードと、自分たちの生息地について考える](https://www.yarakawa.com/single-post/reflections-on-tc26)

自分もそれに近い立場でずっと動いてきたつもりです。TableauユーザーもAIを使わないといけない。両方使った上でTableauの使い方に答えを出す。

そういう人が日本のTableauコミュニティにもう少しいてもいいし、その人がコミュニティタイトルを持ってアンバサダーとして活躍していてもいいのでは、と。

生成AIをもっと発信するTableauユーザーが、日本にいてもいい。肩書をちゃんと持とうと思ったのは、まぁそれだけの話です。

活動自体は変わりません。Tableauへの貢献をしたい、コミュニティに還元したい、という気持ちで書いたり話したりするのはこれまでと同じです。

変わるのは、その活動が何として数えられるか、ですね。

日本のTableau Ambassadorが持つ属性の中に、AI系のトピックをゴリゴリにやる人間、という自分の持っているものを足しに行けたらいいなと。TableauがBIや可視化だけでなく生成AIの色もちゃんと持っている、ということを、コミュニティの側面からも支えられたら嬉しいです。

5月の記事の末尾に「DatafamがもっとAgent-nativeになれば嬉しく、また自分の発信もそのような内容を続けたい」と書いていました。今年はその続きを肩書付きでやることになります。

### Keynoteのあとで

そんな中で今回のKeynoteでした。見終わっての感想は、自分の役割の見え方は全く変わっていない、でした。

Tableauが可視化ツール、BIツールとしてではなく、生成AIを取り入れながらデータを見て理解してアクションすることを支えるツールへメッセージを強めたのは、高評価です。自分の立場も、TableauユーザーもAIを使わないといけない、両方使った上で答えを出す、で前から変わっていません。

変わったと思っているのは、Tableauが打ち出すTableauユーザーの像の方です。

Tableauはずっと可視化ツールでありBIツールで、Tableauユーザーといえば、Creator / Explorer / Viewerのライセンスの中で可視化を作る人と見る人でしたよね。可視化を作るのではなくBIプラットフォームの中のデータにAPIやMCPで入っていくユーザーは、使う道具もスキルセットも生成AIの習熟度も違います。

なので今までのTableauユーザーとは属性が違うのではと思っていました（自分も「Tableau MCPユーザー」のような別の名前を考えていたくらいです）。

Keynoteのあとは、MCPもAIも全部含めて使って、使えて、Tableauユーザーです。Tableau Studioの中でも普段のAIツールの中でも生成AIと協業して分析する人を、Tableau自身がTableauユーザーとして提示してきました。

![Keynoteのあとは、MCPもAIも使う人が別属性ではなく、同じTableauユーザーの内側に濃淡を持って並ぶ](images/tableau-user-before-after.png)

名前の話がしたいわけではなくて、Keynoteの世界観は我々Tableauユーザーに、生成AIの世界観への習熟を求めている、という話だと受け取っています。AIをバリバリ使ってTableauも使っている人と、AIはまだあまり使えていない人が、同じTableauユーザーの内側に並ぶことになる。

後者を入り口の手前に置くのではなく、同じ内側に置いて考えたいと思っています。

TC26では控えめだと感じたTableau側からのユーザーの変化に関するメッセージが、DF26では「AIを中心に据えたTableau」まで来ました。自分が6月から9月にかけて書いてきた、AI Agentとの付き合い方、Analytics Engineering、AI🤝BIと同じ向きです。

- 参考：AI Agentとの付き合い方についての記事（6月） [AI案・要確認: 公開URL]
- 参考：[TableauにAnalytics Engineeringを持ち込む実験について](https://www.yarakawa.com/single-post/analytics-engineering-for-tableau)

ということで、今年はこの向きのまま、Tableau Ambassadorとしても発信していきます。
