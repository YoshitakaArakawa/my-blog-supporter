## 各観点

### 観点1: Keynote が伝えた世界観の変更を、自分の言葉で捉え直す
- 主張: 主題（trust と speed で agentic analytics enterprise へ）はある意味当たり前。「大きめの世界観の変更」と感じたのは新製品の側、特に Tableau Studio と Tableau Data Apps。 [著者]
- 根拠・背景:
  - Studio は Tableau Desktop の完全なリブランディング・再構成。その時点で「Tableau とは何か」「Tableau というアプリで何をするのか」の世界観が大きく変わった。 [著者]
  - Data Apps は、ユーザーを Studio に閉じ込めず、他の製品（Claude・ChatGPT 等）を使いたい時も MCP やプラグインでサポートする。「Tableau がサポートする世界観」。 [著者]
  - 今までは「Tableau という製品の上に AI 機能（Tableau Agent 等）が乗る」形。今は「AI を中心に据えた Tableau 体験」を作ろうとしている。ここに注目しており、これが大きな変化。 [著者]
  - 一言でいうと「Tableau の上に AI」から「AI を中心に据えた Tableau」への反転。 [AI整理・著者承認 20260922]（著者: 自分も今回の Keynote に同じイメージを持っている）
- Trusted Foundation（3要素の3）を「好き」に入れなかった理由: 当たり前の話だと思っていたから。 [著者]
- 「self-service から at your service へ」: Slack の話が主で、画期的とは思わない。強く響かなかった。記事では「こういう議論もある」と紹介する程度。 [著者]
- 「可視化・従来 BI の話が少ない」という事実の語り方: 当然の帰結として書く。寂しさに寄り添うより「こう進むのだから合わせた方がいい」。応援するトーン。事実は突きつけるが、行動を促す形にする。 [著者]

### 観点2: 「Tableauユーザー」の再定義
- 主張: MCP も AI も全部含めて使って／使えて "Tableau ユーザー"。Studio と Data Apps の両方から来た世界観で、両方とも Tableau 自身が提示している。 [著者]
- 根拠・背景:
  - 別属性（Tableau MCP ユーザー等）が要ると感じていた背景: Tableau はずっと可視化ツール・BI ツールだった。可視化を作るツールから離れて、Tableau という BI プラットフォームの中のデータに API・MCP で入っていくユーザーは、今までの Tableau ユーザーとは属性が違うのではと正直思っていた。 [著者]
  - 違いの中身: 使う道具の違い＋その道具を使うためのスキルセット・生成 AI 習熟度の違い。 [著者]
  - [AI整理] Keynote が Studio（アプリの中に AI）と Data Apps（AI の中に Tableau）を同時に出したことで、両方向から「Tableau ユーザー」の外延が広がり、別名の必要が消えた。
- 読者との関係: 再定義された Tableau ユーザーには両方いる。AI をバリバリ使って Tableau も使っている人と、「AI はまだあまり使えていない」人。後者を入り口の手前に置くのではなく、同じ Tableau ユーザーの内側に置く。 [著者]
- 素材: B-1・B-2（20260918 の連投）／C-3（Studio）・C-6（Data Apps）のスクリーンショット／Libby Nel「The same thing goes for ChatGPT and the same thing goes for Claude」[29:10]。

### 観点3: なぜ推薦を断ってきて、なぜ今年は引き受けたか
- 主張: 自分の中のアンバサダー像（製品のアンバサダー活動・可視化のパワーを伝える・コミュニティ運営・発信）は、自分以外にもできることで、自分がブログでやりたいこととマッチしていないと正直思っていた。 [著者]
- 根拠・背景:
  - 公式の定義文が「shine the spotlight on new voices, innovative ideas」や「try out new things and push us to get better」に触れていることを、著者は知らなかった。 [著者]

  - TC26 の記事（20260512）に決めた時の思考がすでに書かれている: 「Tableau 側からのユーザーの変化に関するメッセージは控えめ。他方、コミュニティリーダー（Visionary）には、変化すること、拡張すること、先に行くことを雄弁に主張している人たちがいた」「Datafam がもっと Agent-native になれば嬉しく、また自分の発信もそのような内容を続けたい」。応募締切（20260716）より前の記述で、引き受けた動機の一次資料になる。 [著者・既刊]

## 書く工程での追加（20260922、著者）
- 観点1の補強 [著者 20260922]: Keynote で一番好きだったのは「組織の全員を Builder にする」、次が「信頼できる基盤」。今、データを使って何かを作る・可視化する・分析する作業は、Tableau の Creator／Explorer／Viewer というライセンス区分に閉じていない。ライセンスに関わらず、Tableau にあるデータもないデータも、自分のビジネス上の行動や意思決定のために生成 AI に渡して分析やレポートを作ってもらうことは普通にある。全員が Builder になるとは、そういう世界観。それを実現するには、全員がランダムなデータを使う世界ではなく、信頼できるセマンティクス・コンテキスト・データを持つプラットフォームに繋がって、その資産を使える必要がある（1つめと3つめが対）。
- 観点1の Proactive Intelligence の語り方 [著者 20260922]: 製品としては Slack などに届く話が主だが、語りたいのは「Intelligence の方からこちらへやってくる」世界観。Grok のように常にエージェントが動いていて、適切なタイミングで話しかけに来る。Codex や Claude Code はルーチンやスケジュール設定はあるが、基本はこちらが起点で見に行く世界。そうではない世界観もサポートされるのがいい。（観点1の「画期的とは思わない」は、この語り方に置き換える）
- 語り方 [著者 20260922]: 展開1は機能紹介や細かい話を置き、世界観と好きな点を簡潔に。図は作図せず Keynote のスクリーンショットを使い、出典を YouTube 配信の概算時刻で示す。
