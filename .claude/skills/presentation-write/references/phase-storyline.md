# 組む工程（storyline.md）

## 入力

- `core.md`（必須。特に「読者」＝聴衆と「読後」＝聞き終えた後）
- `thinking.md`（必須。主張と素材）
- `event.md`（あれば。持ち時間・観客層・規定）
- `references.md` と `$OUTPUT_DIR/references/`（あれば）

## 1. 一言と、観客の From → To

段を組む前に、次の3行を著者と決める。

- **一言でいうと**: thinking.md のコアメッセージから、この登壇で一番持ち帰ってほしい一文
- **From**: 観客が会場に来た時に思っていること・知っていること
- **To**: 帰る時に思っていてほしいこと・してほしいこと。core.md の「読後」と食い違わないこと。食い違えば「核を変えるか」を聞く（不変条件3）

一言は著者の言葉で決める。AI は thinking.md から候補を出してよいが、`（仮）` を付ける。

## 2. 段の叩き台

AI が thinking.md の主張から段の叩き台を出し、各段に根拠の観点（thinking.md のどの主張・素材か）を添える。著者が並べ替え・削除・統合して固める。

- 段の数は持ち時間から機械的に決めない。To に届く順に並べる
- 観客が初めて聞く語・概念は、使う段より前に説明の段（または説明の一言）を置く
- 反応（拍手・歓声）を求める位置は、盛り上がる瞬間（数字や画面を見せた直後）に置き、誰に・何に向けたものかを決める
- 共同登壇なら、自分の持ち場の段だけを書き、前後の話者との受け渡しを最初と最後の段に書く

## 3. storyline.md の書式

```markdown
# ストーリーライン: {タイトル案}

一言でいうと: {一文}
From: {観客が来た時}
To: {帰る時}（核: 読後）

## 1. {段の名前}
ねらい: {この段で観客に起こすこと}（核: {効く行}）
見せる: {画面で見せる証拠の要点。口では細かく話さない}
話す: {台詞の要旨。著者の言葉は（著者）、AI の言い回しは（仮）}
反応: {求めるなら、誰に・何に向けて}
観客: {段の後に、観客が分かっていること・感じていること}
```

- 時間配分とスライドの作り方（レイアウト・枚数）は書かない。deck.md で決める
- `話す:` は要旨に留める。台詞の全文は deck.md で書く

## 4. 確定後

`drift storyline` を提案し（著者が頷いたら実行する）、著者に返すのは storyline.md のパスと段の名前の並びだけにする。
