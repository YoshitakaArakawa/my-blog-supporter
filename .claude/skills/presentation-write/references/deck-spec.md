# deck.md の書式

## 全体の形

```markdown
# デッキ: {タイトル}

> ℹ️ 進捗: {手順ごとのチェックリスト}
> ℹ️ 著者判断: {会話で決まったこと（yyyymmdd）}

## サンプル製品の機能は、1年で 5 から 50 に増えた
段: 2
役割: 数字
画面: なし
本文:
- 機能の数 5 → 50
見せる: figures/fig_feature-growth.png
出典: {日付}時点　出典：{資料名}
秒: 25
核: 現在地
反応: 拍手（開発チームへ）
メモ: グラフの細かい数字は読み上げない

> （仮）最初は5つだった機能が、1年で50に増えました
> （著者）このペースで作ってくれている開発チームに、拍手！
```

- `# デッキ:` の後に ℹ️ メモ（引用ブロック）を置く。スライドより前の行は、スライドに数えない
- スライドは `##` の行から次の `##` の行まで。deck.md にはスライドだけを書く

## 項目

| 項目 | 必須 | 中身 |
|---|---|---|
| `##` の行 | ○ | 主張の一文。`##` の行だけを順に読んで話が通ること（ゴーストデッキ）。構造のスライド（表紙・区切り・まとめ・終わり）はラベルでよい。AI が起こした見出しは末尾に `（仮）` |
| `段:` | storyline.md があれば○ | storyline.md の段の番号 |
| `役割:` | ○ | 内容の役割で、レイアウトの名前ではない。語彙は 表紙・区切り・主張・図・画面・数字・引用・問い・まとめ・終わり |
| `画面:` | | スライドに出す見出し。省略時は `##` の行をそのまま出す。改行は `／`、出さない時は `なし` |
| `本文:` | | スライドに載せる短い文（箇条・ラベル）。続く `- ` の行が値 |
| `見せる:` | | 証拠。図なら `figures/{名前}.png`、画面なら画像のパスか、撮る画面の説明 |
| `出典:` | | スライドの下端に出す出典の行 |
| `秒:` | ○ | この1枚にかける時間の目安（数字1つ） |
| `核:` | 構造のスライド以外は○ | 効く core.md の行（問い／読者／読後／動機／現在地）。複数なら `・` で区切る |
| `反応:` | | 拍手・歓声などを求める位置と、向け先 |
| `メモ:` | | 話さない注意（読み上げない数字、写り込みの注意、言い回しの出どころ）。スライドに出さない |
| 引用ブロック | | 台詞。スライドにもスピーカーノートにも入れない（ノートを使う時は著者が Slides で入れる）。行頭に `（著者）` か `（仮）` の印を付ける |

## 見出しの書き方

- 見出しは主張の一文にし、画面の中身はそれを支える証拠にする
- 通らない所は、見出しの言い換えより先に、並びと段を疑う
- 主張は先に言う。否定から入る見出し（「X ではなく Y」型）にしない
- 画面に出す見出しは2行以内
- AI は見出しの形（一文か、長さ、通るか）だけを点検し、言い回しを押し付けない

## 画面の文字の言葉

- 根拠の無い強調語（「本当に」「圧倒的」「劇的に」など）を使わない。数字があれば数字で言う
- 比喩は、平叙の語で言えない時だけ使う
- 項目の数を3つに揃えない。数は中身で決める
- 画面の文を台詞でそのまま読み上げない。キーワードや専門用語は画面に出してよい

## 台詞の言葉

- 著者の声を優先し、規範で均さない
- 画面は主張と証拠、台詞は説明と呼びかけを担う。画面に無い補足は台詞に置く
- 反応を求める時は、誰に・何に向けたものかを先に言う
- 台詞は全文で書いてよい。読み上げるためではなく、言うことを固めるためのもの

## 時間

- 台詞の字数 ÷ 300字/分（config の `charsPerMinute`）を、その1枚の台詞の時間の上限寄りの目安にする。リハーサルで計ったら、`秒:` を実測に置き換える
- 台詞は `秒:` より短くてよい（指し示す間や反応の間がある）
- 枚数を持ち時間から決めない。枚数は台詞の量と見せる証拠の数から決まる
- `秒:` の合計が event.md の `時間:` を超えたら、削る段を著者に返す
