# deck.md の書式

## 目次

- 全体の形
- 項目
- 見出しの書き方
- 画面の文字の言葉
- 台詞の言葉
- 時間の見積もり
- lint とストーリーボード

## 全体の形

```markdown
# デッキ: {タイトル}

> ℹ️ 進捗: {手順ごとのチェックリスト}
> ℹ️ 著者判断: {会話で決まったこと（yyyymmdd）}

## Tableau MCP の道具は、1年半で 4 から 143 に増えた
段: 2
役割: 数字
画面: なし
本文:
- 道具の数 4 → 143
見せる: figures/fig_06_tools-growth.png
出典: 2026年11月1日時点　出典：GitHub tableau/tableau-mcp
秒: 25
核: 現在地
反応: 拍手（開発チームへ）
メモ: 右のカードの数字は読み上げない

> （仮）最初は4つだった道具が、1年半で143に。改修は累計で400回を超えました
> （著者）毎月こんなペースで進化させてくれている開発チームに、拍手！
```

- `# デッキ:` の後に ℹ️ メモ（引用ブロック）を置く。スライドより前の行は、スライドに数えない
- スライドは `##` の行から次の `##` の行まで。1枚1つの `##`
- deck.md にはスライドだけを書く。検討の記録は ℹ️ メモか thinking.md に置く

## 項目

| 項目 | 必須 | 中身 |
|---|---|---|
| `##` の行 | ○ | 主張の一文。`##` の行だけを順に読んで話が通ること（ゴーストデッキ）。構造のスライド（表紙・区切り・まとめ・終わり）はラベルでよい。AI が起こした見出しは末尾に `（仮）` |
| `段:` | storyline.md があれば○ | storyline.md の段の番号 |
| `役割:` | ○ | 内容の役割で、レイアウトの名前ではない。語彙は 表紙・区切り・主張・図・画面・数字・引用・問い・まとめ・終わり。役割からレイアウトへの対応は presentation-slides が持つ |
| `画面:` | | スライドに出す見出し。省略時は `##` の行をそのまま出す。改行は `／`、出さない時は `なし` |
| `本文:` | | スライドに載せる短い文（箇条・ラベル）。続く `- ` の行が値 |
| `見せる:` | | 証拠。図なら `figures/{名前}.png`、画面なら画像のパスか、撮る画面の説明 |
| `出典:` | | スライドの下端に出す出典の行 |
| `秒:` | ○ | この1枚にかける時間の目安（数字） |
| `核:` | 構造のスライド以外は○ | 効く core.md の行（問い／読者／読後／動機／現在地）。複数なら `・` で区切る |
| `反応:` | | 拍手・歓声などを求める位置と、向け先 |
| `メモ:` | | 話さない注意（読み上げない数字、写り込みの注意、言い回しの出どころ）。スピーカーノートに入れない |
| 引用ブロック | | 台詞。スピーカーノートに入る。行頭に印を付ける: 著者の言葉は `（著者）`、AI の言い回しは `（仮）` |

## 見出しの書き方

- 見出しは主張の一文にし、画面の中身はそれを支える証拠にする（Assertion-Evidence。主張の見出しと視覚的な証拠の組み合わせが、話題だけの見出しと箇条書きより理解を助けたという実験がある）
- `##` の行だけを順に読んで話が通るかを、書く前と書いた後に確かめる。通らない所は、見出しの言い換えより先に、並びと段を疑う
- 主張は先に言う。否定から入る見出し（「X ではなく Y」型）にしない
- 画面に出す見出しは2行以内。上限の字数は config の `titleCharsMax`
- 見出しは著者が決める。見出しが話し手の自由を縛るという批判もあるので、AI は形（一文か、長さ、通るか）だけを点検し、言い回しを押し付けない

## 画面の文字の言葉

組み込みの google-workspace スキル（`references/slides.md` の slide copy）の規範を、日本語に読み替えて使う。

- 根拠の無い強調語（「本当に」「圧倒的」「劇的に」など）を使わない。数字があれば数字で言う
- 比喩は、平叙の語で言えない時だけ使う
- 項目の数を3つに揃えない。数は中身で決める
- 画面の文は、台詞でそのまま読み上げない（Mayer の redundancy の原則。効果は小さいので、lint は知らせるだけ）。キーワードや専門用語は画面に出してよい

## 台詞の言葉

- 著者の声を優先し、規範で均さない。会話体で話す方が伝わる（Mayer の personalization の原則）
- 画面は主張と証拠、台詞は説明と呼びかけを担う。画面に無い補足は台詞に置く
- 反応を求める時は、誰に・何に向けたものかを先に言う
- 台詞は全文で書いてよい。読み上げるためではなく、言うことを固めるためのもの。本番で見る要点だけのノートを別に持つかは著者が決める

## 時間の見積もり

- 台詞の字数 ÷ 話す速さ（config の `charsPerMinute`、既定は 300字/分）を、その1枚の台詞の時間の目安にする。日本語の話す速さは約300字/分、速い人で400字/分とされる
- 見積もりは上限寄りの目安。リハーサルで声に出して計ったら、`秒:` を実測に置き換える
- 台詞は `秒:` より短くてよい（指し示す間や反応の間がある）。見積もりが `秒:` を超えた時だけ直す
- 枚数を持ち時間から決めない。LT は1枚15秒前後・5分で20枚前後になりやすく（高橋メソッドの慣習）、学術発表は1分に1枚までが目安とされる。枚数は台詞の量と見せる証拠の数から決まる
- `秒:` の合計を event.md の `時間:` と比べ、超えたら削る段を著者に返す

## lint とストーリーボード

`scripts/lint-deck.mjs` が数えるもの（判定は警告で、ブロックしない）:

- 必須項目の欠け（`役割:`・`秒:`、構造のスライド以外の `核:`、storyline.md がある時の `段:`）と、語彙外の値
- `秒:` の合計と持ち時間
- 台詞の見積もり時間が `秒:` を超えた1枚
- 画面の見出しの字数の上限超え
- 画面の文を台詞がそのまま含む箇所
- 印の無い台詞と、`（仮）` の残り（見出し・台詞）

`scripts/render-deck.mjs` が `preview/deck.html` にストーリーボードを書く。上半分が見出しだけの並び、下半分が1枚ずつのカード（画面に出るもの／役割・秒・核・反応・台詞・メモ）。生成物なので手で直さず、deck.md を直して再生成する。
