# Wix との同期

記事の作業層（`output/{yyyymmdd}_{テーマ}/`、以降 `$OUTPUT_DIR`）と Wix ブログの下書きを、Wix Blog API で行き来させる。手作業の転記・画像の差し込み・ブラウザ経由の取り込みを置き換える。

引数: `$ARGUMENTS`（1つ目がテーマ、2つ目が操作。どちらも任意）。操作が無ければ著者の発言から決める。スクリプトは `node ${CLAUDE_SKILL_DIR}/scripts/wix-sync.mjs <コマンド>` で実行し、使い方はスクリプト冒頭のコメントにある。

## 規範

- **Wix に書くのは著者の承認を得てから**。push（新規・更新とも）の前に、何をどの下書きへ流すかを示して承認を取る。pull は Wix を読むだけなので承認は要らない。
- **流す元は著者が選ぶ**。`draft.md`（AI 版）を流すと、AI の文が Wix 上の初期値になる。承認を取る時に「自分の言葉で書き直す下地として流す」ことを一言添える。`draft.md` から作った下書きのタイトルには `[AI下書き]` が付く。外すのは著者。
- **公開はしない**。公開・公開予約は Wix の画面で著者が行い、スクリプトにもその経路は無い。公開済みの記事は、下書き（未公開の変更）だけを置き換えられる（下記「公開済みの記事を更新する」）。公開版は著者が Wix の画面で公開するまで変わらない。
- **Wix 側が正**。著者が Wix で書き始めたら、ローカルからの更新（`push --update`）は次の順でだけ行う: pull → 差分を著者に見せる（`/revise` の show）→ 承認。
- **スクリプトが止まったら著者に返す**。止まるのは、前回の同期以降に Wix 側かローカル側で直しが入った時。理由をそのまま伝え、どちらを正にするかを著者が決める。`--force` は著者の指示がある時だけ付ける。
- **全文を会話に貼らない**。返すのは、スクリプトの出力の要約（字数・見出し数・図の数）と編集画面の URL。

## 手順

### 準備（初回だけ）

1. `check` で認証を確かめる。失敗したら README「Wix 連携」の手順で `.env` を置いてもらう。
2. 記事が Wix の投稿に結び付いているかを見る（`$OUTPUT_DIR/wix.json` の `draftPostId`）。
   - 結び付いておらず、著者が Wix で既に書き始めている、または公開済みの場合: `list` で最近の投稿を出し、著者にどれかを確かめてから `link $OUTPUT_DIR <postId>` を実行する。別の投稿に結び付いている記事を結び付け直す時は `--relink` を付ける（同期時点がその投稿の現在になる）。
   - これから下書きを作る場合: 結び付けは push が行う。

### 下書きを作る（push）

1. `push $OUTPUT_DIR/draft.md --dry-run` で変換を試し、構造の要約（見出し・図の数）と、未作図のプレースホルダーの有無を確かめる。
2. 著者に「何を流すか・図の数・タイトルに付く印」を示して承認を取る。合わせて URL slug（`https://www.yarakawa.com/single-post/{slug}`）の候補を3つ添える。小文字英語・ハイフン区切り・2〜5語で、日本語のローマ字化はせず主題を英語で言い直す。同じ主題の既刊があれば年月の接尾辞（例: `-2026-09`）で区別し、既存の `published/*/published.md` の取得元 URL と衝突しないことを確かめる。slug を設定するのは著者（Wix の画面）。
3. `push $OUTPUT_DIR/draft.md` を実行し、出力の編集画面の URL を著者に返す。

### 取り込む（pull）

- 下書きの最新: `pull $OUTPUT_DIR` を実行する。`draft_user.md` が上書きされる。
- 公開版: `pull $OUTPUT_DIR --published` を実行する。`published.md` が上書きされ、出力に slug が出る。取り込めたら記事は Wix で公開済みなので、`published/{記事}/` が無ければ「リポの公開層に反映しますか」と `/promote-to-public` を提案する。

取り込みの後、見出しの数と末尾の段落が Wix の画面と合っているかを1度確かめる。

本文は拡張記法つきの Markdown で戻る。記法の一覧は [references/markdown-extensions.md](references/markdown-extensions.md)。要点:

- 文字色・下線: `[テキスト]{.accent}`・`[テキスト]{.u}`。名前と色の対応は `scripts/wix-styles.json`
- 画像: push で上げた画像はローカルのパス、著者が Wix で入れた画像は `![…](wix:<Media の ID>)`。幅は `{width=small}` などの属性
- X のポスト: `::x{url=… width=… height=…}`。それ以外の Markdown にできないノード: `::wix{type=… id=…}`
- 空段落の数・段落の中の改行: `<!-- 空段落: n -->`・`<br>`。印の行は消さない・動かさない

文字サイズ・文字揃え・画像の切り抜きなど記法の無い装飾を持つ段落は、`wix.json` に控える。直さなければ push で控えのまま戻る。出力の「Markdown に書けない装飾のある段落」がその数。

取得した下書きは `$OUTPUT_DIR/wix-snapshots/pull_{編集日時}.json` に、Ricos の JSON のまま残る。Wix Blog API に版の履歴は無いので、下書きを戻す時の手がかりはこれだけになる。

### ローカルの直しを Wix に送る（update）

`/revise` の apply などで `draft_user.md` を直し、Wix へ反映したい時に使う。

1. 著者に送る差分を示して承認を取る。
2. `push $OUTPUT_DIR/draft_user.md --update --dry-run` で点検する（見方は「公開済みの記事を更新する」の手順4）。
3. `push $OUTPUT_DIR/draft_user.md --update` を実行する。置き換わるのは本文だけで、タイトルは Wix 側のまま。上書きする直前の下書きは `wix-snapshots/before-push_{編集日時}.json` に残る。
4. Wix 側に取り込んでいない直しがあると、スクリプトは止まる。その時は pull して差分を見せ、手順1からやり直す。

### 公開済みの記事を更新する

公開中の記事に推敲を反映する時、または旧記事を新しい本文に差し替える時に使う。既定は、公開中の記事の下書きを直接置き換えること。試しの非公開の下書きは作らない。置き換える前に記事は非公開の複製として残り、公開版は著者が Wix の画面で公開するまで変わらないため。

1. 記事が対象の投稿に結び付いていなければ、著者に確かめて `link $OUTPUT_DIR <postId> --relink` を実行する。
2. `pull $OUTPUT_DIR` で下書きを取り込む。同期時点・画像・装飾の控えがここで揃う。
3. 本文を直す（`/revise` の show → 著者の採否 → apply）。
4. `push <file.md> --update --allow-published --dry-run` で点検する。出力の「点検」に、直前の pull の控えと比べて減る装飾、消える画像、位置や幅が変わる画像が出る。
   - 位置が変わる画像があれば送らない。本文の画像の行を確かめて点検をやり直す。
   - 「控えた段落のうち本文に見当たらない」が出たら、その段落の装飾は送ると消える。一覧を承認の時に著者へ示す。
5. 著者の承認を得て `push <file.md> --update --allow-published` を実行する。スクリプトは置き換える前に、記事を非公開の下書き `[複製 {yyyymmdd}] {タイトル}` として Wix に複製し、JSON も `wix-snapshots/` に残す。置き換わるのは下書きの本文だけで、タイトル・公開版は変わらない。控えた段落が消える時は止まるので、著者が装飾を捨ててよいと言った時だけ `--accept-loss` を付ける。
6. 編集画面の URL を返し、タイトルの差し替えと公開は著者が Wix の画面で行うと伝える。

## 制約

- **インラインコード**: Wix に対応する装飾が無いので、地の文で送る。
- **記法の無い装飾**: 文字サイズ・背景色・文字揃え・画像の切り抜き・コードブロックの中の太字など。控えた段落を直すと消えるので、push は止まる（`--accept-loss` で送る）。Wix の画面で直すのが確実。
- **コードブロックの中のリンク**: リンクとみなすのは `[テキスト](URL)` のうち、URL が `http://`・`https://` で始まり空白と括弧を含まないものだけ。字面のまま残したい `[x](https://…)` は控えに入り、中身を変えなければ字面のまま戻る。
- **新しく書いた `::x`**: 枠の高さは仮の値。Wix の画面でポストの長さに合わせて調整する。
- **旧形式の印**: 記法を入れる前の pull が書いた `<!-- 画像 -->`・`<!-- Wixのノード -->` は push が読める。ただし旧形式の画像の印の数が pull の時と違うと、別の画像にずれるので止まる（詳細は references）。次の pull で新しい記法に置き換わる。
- **公開済み記事の更新**: 下書き（未公開の変更）の置き換えだけができる（`--allow-published`）。公開予約中の記事は置き換えない。公開版への反映は著者が Wix の画面で公開する。
- **画像形式**: png・jpg・gif・webp に限る。
- **API が使えない時**: 予備の経路は無い。復旧を待つか、著者が Wix の画面で作業する。
