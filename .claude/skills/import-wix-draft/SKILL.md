# import-wix-draft

Wix ブログ編集ページを丸ごと保存した MHTML から、記事本文だけを抽出して `draft_user.md` に書き出す。AI と「現在の下書き」を共有して議論するための取り込み工程。

**この Skill は抽出までを担う。** 書き出したら実行サマリを報告して終わる。議論・推敲はユーザーが別途切り出す。

前提: Python 3（標準ライブラリのみ。追加パッケージ不要）。入力は Wix ダッシュボードのブログ編集ページを保存した MHTML で、内部の記事プレビュー（`single-post` のレンダリング結果）に本文が含まれる。

## 手順

進捗：

- [ ] ステップ1：入力 MHTML を特定する
- [ ] ステップ2：出力先 draft_user.md を決める
- [ ] ステップ3：上書き確認
- [ ] ステップ4：抽出スクリプトを実行する
- [ ] ステップ5：サマリを報告する

### ステップ1：入力 MHTML を特定する

- 引数でパスが渡されたらそれを使う
- 引数が無ければ Glob `output/**/*.mhtml` で探し、最新（mtime 最大）を採用する。複数候補があり最新が意図と異なりそうなら、候補を提示して 1 問だけ確認する
- 1 件も無ければ、その旨を報告して終わる（勝手に他の場所を探さない）

### ステップ2：出力先 draft_user.md を決める

入力 MHTML と同じディレクトリ（記事の出力ディレクトリ `output/{yyyymmdd}_{テーマ}/`）の `draft_user.md` を出力先にする。

### ステップ3：上書き確認

`draft_user.md` が既に存在し中身が非空なら、上書き前にユーザーへ確認する。`draft_user.md` はワークフロー上「ユーザー推敲版」のスロットで、既存の手書き内容を失う恐れがあるため。空ファイルまたは未作成ならそのまま進む。

### ステップ4：抽出スクリプトを実行する

HTML 解析が脆いので、このスクリプトを正確に実行する（抽出方式と構造の復元範囲はスクリプト冒頭の docstring にある）。

```
python ${CLAUDE_SKILL_DIR}/scripts/extract_wix_mhtml.py "<入力.mhtml>" "<出力ディレクトリ>/draft_user.md"
```

成功時は `OK title_chars=... / OK output=... / OK body_chars=... body_lines=... headings=... links=...` を出力する。タイトル文字列は出力 Markdown の先頭にあり、コンソール文字コード非依存にするため stdout には出さない。`error:` で終わった場合は、メッセージをそのままユーザーに伝え、勝手な代替経路（別パートの当て推量抽出など）に逃げない。

### ステップ5：サマリを報告する

`OK` 行をもとに、本文文字数・見出し数・復元リンク数・保存先パスを報告する。タイトルは出力 Markdown の先頭から拾って併記してよい。本文全文はここで貼らない（ファイルにある）。
