# 公開層への昇格

`output/{yyyymmdd}_{テーマ}/`（非公開の作業層、以降 `$OUTPUT_DIR`）から、公開してよい成果物だけを `published/` の同名ディレクトリ（以降 `$PUB_DIR`）へ昇格させる。このリポは Public で、published/ に commit したものは誰でも読める。「思考の過程ごと共有する」方針と「推敲前の生素材・実生活に波及する記述は出さない」線引きを両立させるゲートであり、何を出すかの最終判断は著者が握る（勝手にコミットしない）。

引数: `$ARGUMENTS`（1つ目がテーマ。日付プレフィックス付きのフォルダ名でもよい。`--with-review` を付けた時だけ `review/` も対象に加える）。

## 手順

1. **対象の確認**: `node ${CLAUDE_PROJECT_DIR}/scripts/promote-to-public.mjs {テーマ} --dry-run` を実行し、コピー対象の一覧と上書きになるものを著者に示す。ホワイトリスト（core / references.md / thinking / outline / draft / draft_user / draft_user_* / published.md）と常に除外するもの（`references/` の raw 素材・`wix.json` 等の識別子・画像・途中版）はスクリプトが持つ。
2. **コピーと機械走査**: 同じコマンドを `--dry-run` 無しで実行する。コピー後のファイルを職場語彙・メールアドレス・絶対パス・鍵らしき文字列で走査した結果が出る。走査は見落とし防止の補助で、次の通読の代替にしない。
3. **公開適性の点検**: `$PUB_DIR` 側のファイルを次の5観点で通読し、該当箇所を `ファイル名:行番号` で指摘する。本文は書き換えない。
   1. 職場・人間関係・進退: 離職・転職の意向、同僚・上司・特定個人への評価など、実生活の関係に波及する記述
   2. 本人以外の実名: 記事本文で公開済みの一次体験の言及（登壇者名等）は可。非公開文脈での人物評・私的なやりとりは不可
   3. 第三者素材の転記: X ポスト・記事本文・PDF の長文写しが残っていないか（要旨化・短い引用＋出典は可）
   4. 公開版で落とした生素材: 公開記事（draft_user.md）と照らし、著者が載せないと判断した内心・感情の一次素材が core / thinking に残っていないか。残っていれば「これも公開してよいか」を個別に確認する
   5. 認証情報・識別子: トークン・メールアドレス・アカウント ID・個人マシンの絶対パス
4. **著者の承認**: 点検結果（指摘ゼロならその旨）とコピーした一覧を提示し、判断を待つ。指摘への対処（削除・言い換え・そのまま公開）は著者が決め、実施は `$PUB_DIR` 側にだけ行う。`$OUTPUT_DIR` の原本は変えない。
5. **コミット**: 承認後に `$PUB_DIR` を git add し、`published: {テーマ} の記事成果物を公開` の形でコミットする。承認前にコミットしない。push は著者の指示があった時だけ。
6. **公開版を基準として固める**: `node ${CLAUDE_PROJECT_DIR}/scripts/revise.mjs freeze $OUTPUT_DIR/draft_user.md` を実行し、公開時点の本文を `$OUTPUT_DIR/revision/baseline.md` に保存する。公開後の追記や修正は `/revise` がこの基準からの差分で示す。
7. **告知**: X での告知文案が要るかを著者に聞き、要るなら `/announce-article` に渡す。
