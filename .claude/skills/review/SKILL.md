# 記事レビュー

記事の成果物を lens ごとの視点で点検し、指摘を `review/{lens}_NN.md` に書き出す。

このスキルは隔離コンテキスト（`context: fork`）で実行される。会話履歴にはアクセスできないため、対象と基準はすべてファイルから読む。書いた当人から切り離された別エージェントが「文書として」読むことで、自分の成果物を自分で擁護する経路を断つ。メイン会話には**実行サマリのみ**を返す。指摘の全文を戻り値に詰めない。

## 共通規律（全 lens に効く）

1. **core.md が北極星**。最初に読む。指摘の優先順位は「core.md のどの行にどう効くか」で決め、各指摘に効く core 行（問い／読者／読後／動機／現在地）を付す。名指しできない指摘は駐車場へ回す
2. **著者に返す指摘は最大3件**。4件目以降は出力ファイルの「駐車場」節に書き、サマリには件数だけ伝える
3. **主題を深める指摘と、鎧を増やすだけの指摘を分ける**。想定反論の先回りを増やすだけで主題が深まらない指摘は駐車場へ。反論への答えが主題を深める時だけ本体の指摘に置く
4. **成果物を書き換えない**。指摘と方向性の提案に留め、対象ファイルを編集しない。採否は著者が決める
5. **重複を避ける**。既存の `review/{lens}_*.md` を読み、指摘済みの論点は繰り返さない。前回の指摘が解消されていなければ「未対応」と印を付ける
6. **忖度しない**。良い点を水増ししない。ただし指摘には対象の該当箇所（引用または行番号）を必ず添え、印象論だけの指摘にしない

## 手順

### 1. 引数の解釈

- テーマ: `$0`
- lens: `$1`
- 対象: `$2`

上の3行は起動時に実引数へ置換される。lens 欄が空、置換されずに残っている、または `critique` / `drift` / `readers` / `author` のいずれでもない場合は、**点検せずに終了する**。「lens が指定されていない（または不正）ので点検していない。`critique`（主張を叩く）／`drift`（前段からのズレ）／`readers`（初見読者の通読）／`author`（著者下書きの編集レビュー）から指定してください」という旨をサマリで返す。**推測で lens を選ばない**。

対象欄の意味は lens ごとに違う（lens=drift は stage、lens=readers / author はファイル名）。既定値は lens ファイルに書いてある。

### 2. 出力ディレクトリと core.md

出力先は `output/{yyyymmdd}_{テーマ}/`。`output/` を Glob し、`_{テーマ}` で終わるフォルダを採る（テーマに日付プレフィックスが付いていればそのまま使う）。以降 `$OUTPUT_DIR` はこのディレクトリを指す。

`$OUTPUT_DIR/core.md` を**最初に読む**。無ければ点検せずに「core.md が無いので点検していない。先に `/article` で core.md を作ってください」という旨をサマリで返して終了する。

core.md は記事の核（問い／読者／読後／動機／現在地の5行）であり、全 lens の優先順位判定の基準になる。

### 3. lens ファイルの読み込み

`${CLAUDE_SKILL_DIR}/references/lens-$1.md` を読む。そこに書かれた「入力」を読み込み、「観点」で点検し、「出力テンプレート」の形に整え、「やらないこと」を守る。

lens が `author` の時は、物差しとして `${CLAUDE_PROJECT_DIR}/.claude/skills/article/references/voice-style.md` と同 `cognitive-rhythm.md` も読む。

必須の入力が欠けている場合は、lens ファイルの指示に従って欠落をサマリで報告して終了する。**他ファイルで代替しない**。

### 4. 指摘の組み立て

lens の観点で拾った論点を、共通規律1〜3の順で並べ替える。上位3件が著者に返す指摘、残りが駐車場。

指摘は「なぜ問題か」と「どう直す方向がよいか」をセットで書く。書き換え案そのものは書かない。

### 5. 連番の決定とファイルの生成

`$OUTPUT_DIR/review/` 内の既存 `$1_NN.md` を確認し、最大番号 + 1 を今回の番号とする（2桁ゼロ埋め）。1つも無ければ `01`。lens ごとに独立した連番を振る。`review/` フォルダが無ければ作成する。

過去の指摘が上書きで消えず、ループごとの変遷が時系列で残る。

`$OUTPUT_DIR/review/{lens}_{NN}.md` に、次の共通骨格で書き出す。`{見出し}` と、`## 指摘` の各項目、lens 固有の追加節は lens ファイルの出力テンプレートに従う。

```markdown
# {lens の見出し} #{NN}（{yyyymmdd}）

## 対象
{点検した対象ファイルと、core.md の「問い」行を1行で}

## 前回からの変化
{同じ lens の過去ファイルがあれば、前回指摘が解消されたか／未対応か。初回は「初回」}

{lens 固有の追加節をここに置く}

## 指摘（優先度順・最大3件）

### 1. {見出し}
- 効く core 行: {問い / 読者 / 読後 / 動機 / 現在地 のどれに、どう効くか}
- {lens ファイルが指定する項目}

### 2. {見出し}
...

## 駐車場
- {4件目以降の指摘・鎧を増やすだけの指摘。各1行}

## 総評
{最優先の論点1〜2個と、次に進んでよいかの判断}
```

`{yyyymmdd}` は実行日の日付。指摘が1件も無い場合は `## 指摘` に「指摘なし」と明記する。駐車場が空なら「なし」と書く。

### 6. 実行サマリを返す

メイン会話には、著者がファイルを開かずに採否を判断できる箇条書きサマリを返す。ファイルの全文は詰めない。

```
lens: {lens}／対象: {対象}／ファイル: review/{lens}_{NN}.md

指摘（最大3件）:
- {見出し}（core: {効く core 行}） — {一言で、何がどう弱いか}
- …（1件も無ければ「なし」の1行）

駐車場: {N}件
判断: {次に進んでよい／戻して直すべき、を1行}
```

規律:
- 指摘は1件ずつ箇条書きにし、各行は「見出し＋効く core 行＋一言」で完結させる
- 駐車場は件数だけ伝える。内容はファイル側に置く
- 指摘が1件も無い場合も、上記フォーマットで「指摘: なし」「判断: 進んでよい」を明示する
- Write に失敗した場合は inline で指摘本文を返さず、「点検は実行したが保存に失敗」とサマリで明示する
