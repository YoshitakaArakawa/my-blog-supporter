# lens: audience（観客として通しで聞く）

## 目次

- 入力
- 観点（ペルソナの設計／聞く体験／構成と画面）
- 出力テンプレート
- やらないこと

登壇の `deck.md` を、**会場の観客として1回だけ、時間どおりに聞く**体験として受け取る。どこで置いていかれるか、何が残るか、聞き終えた後に何が変わるかを予測する。

観客は読者と違い、読み返せず、ペースも自分で決められない。画面は数秒しか見ず、台詞は一度しか聞かない。この lens は、その条件で中身が届くかだけを見る。

## 入力

- **対象**（必須）: 対象欄（`$2`）が `.md` で終わるならそのファイル名、それ以外・空なら既定の `deck.md`。`$OUTPUT_DIR/{対象ファイル名}` を読む。無い・空の場合は「対象が見つからないので点検していない。先に `/presentation-write` で書く工程を回してください」という旨をサマリで返して終了する
- `core.md` の「読者」行（＝聴衆）と「読後」行**だけ**をペルソナ設計に使う。「動機」「現在地」行は優先順位の判定に使うだけで、ペルソナには持ち込まない
- `event.md`（あれば）: 場と観客層の記述
- `thinking.md` / `storyline.md` / `references.md` は**読まない**。観客はこれらを知らない

**観客に見えない・聞こえない要素を除外する**: `メモ:` の行と、deck.md 冒頭の ℹ️ メモは著者向けであり、評価の対象から外す。`（仮）` の台詞は「ここに著者の言葉が入る前提」で聞く。

受け取り方: スライドの順に、`画面:`（無ければ `##` の行）・`本文:`・`見せる:`・`出典:` を「画面に出るもの」、引用ブロックの台詞を「聞こえるもの」として受け取る。`秒:` をその1枚にかかる時間とする。

## 観点

### ペルソナの設計

3人を立てる:

1. **主たる聴衆**: core.md の「読者」行をそのまま使う
2. **前提知識の薄い聴衆**: 専門用語や製品名を初めて聞く人。event.md の観客層に合わせて具体化する
3. **前向きな聴衆**: すでに関心があり、持ち帰って試したい人

誰を立てたかは出力に明記する。

### 聞く体験

各ペルソナで通しで聞き、次を記録する:

- **置いていかれた箇所**: 初めて聞く語が説明なしに出た、前の話とのつながりが見えなかった（スライドの見出しと、画面か台詞かの別を添える）
- **数秒で掴めなかったスライド**: 画面に出るものだけで、その1枚の主張が数秒で分かるか
- **残る一言**: 帰り道に人へ話すとしたら何と言うか
- **聞いた後の変化**: core.md の「読後」行が起こるか。起こらないなら何が障壁か

### 構成と画面

ペルソナを離れて次を見る:

- **見出しだけで話が通るか**: `##` の行だけを順に読み、話が途切れる箇所を挙げる
- **主張がどこにも無いスライド**: 見出しにも台詞にも、その1枚の主張が無いもの（表紙・区切り・まとめなどの構造のスライドは除く）
- **切れ目と現在地**: 話の区切りと、いま全体のどこにいるかが観客に分かるか

著者の口調、笑い、あえての脱線は、主題を損なっていない限り指摘しない。観客に届く聞きやすさより、著者の声を優先する。

## 出力テンプレート

見出しは `観客シミュレーション`。`## 対象` 節には「{対象ファイル名}（ペルソナ: {3者の一覧}）」を書く。

lens 固有の追加節として、`## 指摘` の**前**に次を置く:

```markdown
## ペルソナ別の聞く体験

### 1. {主たる聴衆の名前}
- 置いていかれた箇所: {スライドの見出し＋画面か台詞か＋理由}
- 数秒で掴めなかったスライド: {見出し＋理由}
- 残る一言: {帰り道の一言}
- 聞いた後の変化: {予測と根拠}

### 2. {前提知識の薄い聴衆} / ### 3. {前向きな聴衆}
{同構成}

## 見出しだけで読んだ流れ
{`##` の行を順に並べ、話が途切れる箇所に ⚠ を付ける}

## 最大の強み（削らないこと）
{1つ、スライドの見出しつき}
```

各指摘の項目:

```markdown
### 1. {弱点の見出し}
- 効く core 行: {問い / 読者 / 読後 / 動機 / 現在地 のどれに、どう効くか}
- ペルソナ: {どの聴衆がどう躓くか}
- 箇所: {スライドの見出しと、画面か台詞かの別}
- 問題: {観客の体験として何がどう損なわれるか}
- 直し方の方向性: {どう直すか（書き換え案は書かない）}
```

## やらないこと

- 前段ファイルとの照合（lens=drift の領分）
- 主張そのものの是非の議論（lens=critique の領分）
- 色・配置・文字の大きさなど見た目の点検
- 台詞を著者の口調から均す提案
- deck.md の書き換え。指摘の採否は `/presentation-write` の書く工程で著者が判断する
