# lens: author（著者下書きの編集レビュー）

著者が書いた原稿（`draft_user.md`）そのものを、公開前のゲートとして編集視点で点検する。会話の文脈を持たない別エージェントが原稿を冷えた状態で読むことが**初見の読者に近い視点**を生み、「読みにくい」「難しい」の判定精度を上げる。

ここで出た指摘は、著者が推敲で取捨選択するための材料。

## 入力

- **対象原稿**（必須）: 対象欄（`$2`）が `.md` で終わるならそのファイル名、`.mhtml` で終わるなら Wix の下書きとして下の取り込みを先に行い、それ以外・空なら既定の `draft_user.md`。`$OUTPUT_DIR/{対象ファイル名}` を読む。無い・空の場合は「対象が見つからない（または空）ので点検していない。先に下書きを用意してください（Wix なら編集画面を Chrome で開いたまま fetch-page の Wix 下書き手順で取るか、編集ページを .mhtml で保存して `output/{記事}/` に置く）」という旨をサマリで返して終了する。**`draft.md` など他ファイルで代替しない**（著者の原稿を診るのが目的のため）
- **Wix からの取り込み**: 著者が編集画面を Chrome で開いていれば、`fetch-page` スキルの「Wix の編集画面の下書き」手順で `draft_user.md` を取るのが第一の経路（見出し・リンク・画像位置を保ち、会話にトークンを流さない）。それが使えない時の予備として、`draft_user.md` が無いか空で、`$OUTPUT_DIR/*.mhtml`（対象欄で指定があればそれ、無ければ最新）があれば、点検の前に本文を抽出する。Python 3（標準ライブラリのみ）で次を実行する:

  ```
  python .claude/skills/review/scripts/extract_wix_mhtml.py "<入力.mhtml>" "$OUTPUT_DIR/draft_user.md"
  ```

  成功時は `OK ...` の行、失敗時は `error:` で終わる。失敗はメッセージをそのままサマリで報告し、当て推量の抽出に逃げない。`draft_user.md` が非空なら抽出せず既存の原稿を点検する（著者の手書きを上書きしないため。取り込み直す時は著者が `draft_user.md` を空にしてから呼ぶ）。抽出した時はサマリに本文字数・見出し数・リンク数を添える
- `$OUTPUT_DIR/outline.md`・`$OUTPUT_DIR/thinking.md`（あれば。意図した構成・主張と、原稿の実体とのズレを見るのに使う）
- `.claude/skills/article/references/voice-style.md`（**必須。文体整合・表記の基準**。「0. 数値仕様」「1. 実例」を物差しの中心に、ルール1-16＝著者の声・表記規約、ルール17-23＝AI 的傾向への対抗ガイドをレビューのレンズに含める）
- `.claude/skills/article/references/cognitive-rhythm.md`（**必須。認知リズム観点の基準**。判定軸（状況更新か文書更新か）と「症状→処方」の診断表をレンズに使う）
- 機械 lint の結果（**必須**。校正観点の入力）:

  ```
  node scripts/lint-draft.mjs $OUTPUT_DIR/draft_user.md
  ```

  数値仕様の NG・禁止句・textlint の指摘を観点7（校正）と観点6（文体整合）の材料にする。ただし著者の原稿は AI 版と違い、lint の NG が即「直すべき」ではない。著者が意図して選んだ表現（英文引用・箇条書きの太字ラベル等）は、指摘するとしても「voice-style の仕様と外れている」事実の共有に留め、AI 的な均し方を勧めない
- `$OUTPUT_DIR/references.md`（あれば。引用と本文の整合を見るのに使う）

## 観点

原稿を次の8観点で診る。1観点に偏らず一通り当てる。**各指摘は弱点から述べ**、該当箇所を行番号（例: `draft_user.md:42`）で示す。**書き換え案でなく、問題の指摘と方向性の提案**に留める。

1. **タイトル整合**: タイトルと本文の主張（core.md の「問い」「読後」）が合っているか。タイトルが本文の芯を立てているか、弱い/ぼやけていないか。必要ならタイトル案を数点（短い英語 slug が要るなら別途）
2. **構成・流れ**: 展開順序は自然か。結論（payoff）に着くのが遠すぎないか。章間のロードマップ的提示や同じ話の繰り返しが過剰でないか。重み付け（分量配分）は適切か
3. **読みやすさ**: 一文が長すぎないか、段落の切れ目は適切か。難語・専門語が前置きなく出ていないか
4. **想定読者への難易度**: core.md の**「読者」行に照らして**、読者の前提を超える箇所はどこか。最も難しいピークが本筋の手前に来ていないか（離脱リスク）
5. **論理破綻・飛躍**: 主張の間に飛躍・矛盾はないか。未定義の語、前後でズレる定義はないか
6. **文体整合（voice-style）**: voice-style.md のルールに沿っているか。特にルール17-23に照らし、**著者性を均して"AI っぽく一般化する"方向の提案はしない**（著者の声を守る）。voice-style に明文化されていない軸も見る: 抽象と具体の順序、固有名詞・一次情報の量、製品論に寄ってユーザー主体性が薄れていないか、余談やメタファーの効き
7. **校正（誤字脱字・表記ゆれ・係り受け・冗長）**: 表面の精度を機械的に拾う。(a) 誤字・脱字・送り仮名の誤り、(b) 表記ゆれ（同一語の漢字/かな・全角半角・「フィルタ」と「フィルター」等。voice-style.md の「14. 表記辞書／半角スペース／数字／記号」を基準にする）、(c) 係り受けのねじれ（二重受身・二重義務、主述の不一致、修飾の係り違い）、(d) 冗長な言い回し（一文内の同語反復、ほぼ同じ問い・主張の二度立て、「ながら」等の連続）。文意の言い換え（推敲）ではなく、直せば必ず良くなる表面のミスと、読みで引っかかるねじれ・重複に絞る。章をまたぐ構成上の繰り返しは観点2、主張間の飛躍は観点5の領分とし、ここは文・語レベルに留める
8. **認知リズム**: cognitive-rhythm.md を基準に、規約違反ではないのに読み進める推進力が落ちる箇所を診る。(a) 未回収の緊張の不在（問いも見込みも立たないまま説明が続く、立てた問いが回収されない）、(b) 平坦な拍（同型のヘッジ語尾や長文の3連続以上）、(c) 文書更新文（進行実況・節末の予告・空句。判定軸は「その文が更新するのは状況か文書か」）、(d) 密度の平坦（具体と意味づけの往復がなく視点距離が固定）。指摘には診断表（症状→処方）の処方を添える。章構成の問題は観点2、単純な文長は観点3の領分とし、ここは緊張・拍・密度の設計に絞る

## 出力テンプレート

見出しは `下書きレビュー`。`## 対象` 節には「{対象ファイル名} のタイトルと、本文のコアメッセージを一行で」を書く。

lens 固有の追加節として、`## 指摘` の**前**に次を置く:

```markdown
## タイトル
- 現タイトル: {引用}
- 本文との整合: {合う/弱い、理由}
- 案: {必要なら数点}
```

`## 指摘` の**後ろ**に次を置く:

```markdown
## 良い点（任意・簡潔に）
- {維持したい強み。削らないために明記}
```

各指摘の項目:

```markdown
### 1. {指摘の見出し}
- 効く core 行: {問い / 読者 / 読後 / 動機 / 現在地 のどれに、どう効くか}
- 観点: {タイトル整合 / 構成・流れ / 読みやすさ / 読者難易度 / 論理破綻 / 文体整合 / 認知リズム / 校正}
- 箇所: {ファイル名:行番号}
- 問題: {何がどう弱いか}
- 提案: {どう直す方向がよいか（書き換えはしない）}
```

校正（観点7）の指摘は件数が多くなりやすい。最優先の1件だけを共通骨格の指摘に立て、残りは駐車場に「校正 {N} 件」としてまとめ、内訳は駐車場の箇条書きに落とす。

## やらないこと

- 原稿本文の直接書き換え（推敲は著者の領分）
- 主張そのものの是非の議論（lens=critique の領分）
- AI が生成した `draft.md` の代替レビュー（AI 版の点検は lens=drift と lens=readers が担う）
