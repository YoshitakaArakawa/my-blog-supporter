# lens: readers（初見読者として通読）

AI が生成した記事ドラフトを **初見の読者として通読** し、読中体験・読後の反応・行動変化・炎上経路を予測する。ドリフト点検や文体チェックでは出ない種類の問題——どこで読者が離脱するか、どの一文が刺さるか、どの段落が切り取られて燃えるか、読後に行動が変わるか——を公開前に捕まえる。

執筆時の意図や経緯を知らない読者の体験を近似するのが目的。「公開された記事」としてだけ読む。

## 入力

- **対象ドラフト**（必須）: 対象欄（`$2`）が `.md` で終わるならそのファイル名、それ以外・空なら既定の `draft.md`。`$OUTPUT_DIR/{対象ファイル名}` を読む。無い・空の場合は「対象が見つからないので点検していない。先に `/article` で書く工程を回してください」という旨をサマリで返して終了する
- `core.md` の「読者」行と「読後」行**だけ**をペルソナ設計に使う。「動機」「現在地」行は優先順位の判定に使うだけで、ペルソナには持ち込まない——初見読者は著者の意図を知らないため
- `thinking.md` / `outline.md` / `references.md` は**読まない**。初見読者はこれらを知らない

**読者には見えない要素を除外する**: ドラフト冒頭の作業メモ（ℹ️ 引用ブロック）、✍️ 可視マーカー、HTML コメント（画像・リンクのプレースホルダー）は著者向けであり、読者体験の評価対象から外す。✍️ 部分は「ここに著者の一次体験が入る前提」で読む。

## 観点

### ペルソナの設計

3つのペルソナを立てる:

1. **主読者**: core.md の「読者」行をそのまま使う
2. **懐疑側の読者**: 記事の主張に乗らない合理的な読者。記事が想定する反論を実際に抱えている人
3. **前向き側の読者**: すでに主張に共感している読者。シェア・引用するかどうかの目線

記事のテーマに応じて 2・3 は具体化してよい（例: 特定コミュニティの中堅ユーザー、同業の実務者）。誰を立てたかは出力に明記する。

### シミュレーション

各ペルソナで通読し、次を記録する:

- **読中体験**: どこで引き込まれ、どこで離脱しそうになり、どこで反発・疑問を感じたか（該当箇所の引用つき）
- **読後の一言**: その読者が SNS に書きそうなポスト文面を1つ想像する
- **行動変化の予測**: core.md の「読後」行が起こるか。変わらないなら何が障壁か
- **コメント欄の予測**: 書かれそうな指摘・質問・反論

### 編集者視点

ペルソナを離れて次をまとめる:

- **最大の強み1つ**: 推敲で削られないよう明示する
- **直すと効果が大きい弱点**: 該当箇所の引用＋直し方の方向性つき。共通骨格の指摘（最大3件）に載せ、それ以下は駐車場へ
- **炎上・誤読リスク**: 切り取り引用されたとき別の意味になる段落、立場の違う読者に攻撃と映る表現

## 出力テンプレート

見出しは `読者シミュレーション`。`## 対象` 節には「{対象ファイル名}（ペルソナ: {3者の一覧}）」を書く。

lens 固有の追加節として、`## 指摘` の**前**に次を置く:

```markdown
## ペルソナ別の読書体験

### 1. {主読者の名前}
- 引き込まれた箇所: {引用＋理由}
- 離脱・反発した箇所: {引用＋理由}
- 読後の一言（SNS想定）: {ポスト文面}
- 行動変化: {予測と根拠}
- コメント欄の予測: {箇条書き}

### 2. {懐疑側} / ### 3. {前向き側}
{同構成}

## 最大の強み（削らないこと）
{1つ、引用つき}
```

`## 指摘` の**後ろ**に次を置く:

```markdown
## 炎上・誤読リスク
{切り取り・誤読の経路と緩和の方向性。無ければ「なし」}
```

各指摘の項目:

```markdown
### 1. {弱点の見出し}
- 効く core 行: {問い / 読者 / 読後 / 動機 / 現在地 のどれに、どう効くか}
- ペルソナ: {どの読者がどう躓くか}
- 箇所: {該当箇所の引用}
- 問題: {読者体験として何がどう損なわれるか}
- 直し方の方向性: {どう直すか（書き換え案は書かない）}
```

## やらないこと

- 前段ファイルとの照合（lens=drift の領分）
- 主張そのものの是非の議論（lens=critique の領分）。この lens は**読者にどう受け取られるか**だけを見る
- 著者が書いた原稿（`draft_user.md`）の対象化（lens=author の領分）
- ドラフトの書き換え。指摘の採否は `/article` の書く工程で著者が判断する
