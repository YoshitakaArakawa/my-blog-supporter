# lens: critique（主張を叩く）

thinking.md に書かれた主張を批判的に読み、想定反論・前提の穴・論理の飛躍を当てる。批判すること自体が目的ではなく、思考を次の段に進めることが目的。

## 入力

- `$OUTPUT_DIR/thinking.md`（**必須**。レビュー対象の主張メモ）。無い・空の場合は「thinking.md が見つからないので点検していない。先に `/article` で掘る工程を回してください」という旨をサマリで返して終了する
- `$OUTPUT_DIR/references.md`（あれば。主張と参考資料の整合を見るのに使う）

対象欄（`$2`）は使わない。

## 観点

thinking.md の主張・各観点を次の4レンズで叩く。**core.md の「問い」に最も効く穴から順に**当てる。当てる順序は穴の効き方で決め、レンズを一巡させることを目的にしない。

- **想定反論**: 読者や逆の立場の人が「でも〜では？」と返しそうな点。最も強い反論を具体的に立てる
- **前提の穴**: 主張が暗黙に置いている前提のうち、検証されていない・崩れうるもの
- **論理の飛躍**: 「A だから B」の間に飛躍がある箇所。根拠と結論の距離
- **コアメッセージの弱さ**: 主張が当たり前すぎないか、逆に飛躍しすぎていないか。core.md の「読後」行が起こるか

各指摘には「なぜそれが問題か」と「次の一手（どこを掘り直すとよいか）」をセットで書く。叩いて終わりにせず、次の一手に繋げる。

## 出力テンプレート

見出しは `批判レビュー`。lens 固有の追加節は置かない。各指摘の項目:

```markdown
### 1. {指摘の見出し}
- 効く core 行: {問い / 読者 / 読後 / 動機 / 現在地 のどれに、どう効くか}
- レンズ: {想定反論 / 前提の穴 / 論理の飛躍 / コアメッセージ}
- 箇所: {thinking.md の該当主張の引用または行番号}
- 問題: {何がどう弱いか}
- 次の一手: {どこを掘り直すか}
```

## やらないこと

- 著者の主張を別の主張で置き換える提案（掘る・組む工程は `/article` の領分）
- 文章表現・推敲レベルの指摘（書く工程は `/article`、密度の圧縮は `/tighten-draft` の領分）
- 既存記事との重複チェック（公開済み記事側のデータ取得が前提のため、この lens では扱わない）
