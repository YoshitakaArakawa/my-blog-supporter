# X（旧 Twitter）の取得フロー

X はログイン必須。**Cookie をディスクに残さない方針**として、永続プロファイル（`--profile=...`）は使わない。ブラウザプロセスのメモリ上にだけ Cookie を保持し、`close` 時に完全消去する。

named session `-s=x` でブラウザを起動しっぱなしにし、その間 Claude が命令を投げる構成になる。ログインは会話セッション単位で、会話が終われば消える。

## 1. 会話の開始時（Claude がブラウザを起動 → ユーザーがログイン）

X の URL を取得しようとして未ログインを検知したら、Claude が実行する:

```bash
playwright-cli -s=x open https://x.com/login --headed
```

ユーザーの画面に Chromium ウィンドウがポップアップする。コマンドは即座に返るので、続けてユーザーに依頼する:

> 「ブラウザを起動しました。画面のウィンドウで X にログインしてください（2FA 含む）。完了したら『ログインした』と教えてください。ウィンドウは閉じないでください」

ユーザーが手動ログイン後に「ログインした」と返答したら、取得フェーズに進む。

## 2. 取得（ログイン中）

ブラウザは起動したままなので、メモリ上の Cookie でログイン状態が維持されている:

```bash
playwright-cli -s=x goto https://x.com/<user>/status/<id>
playwright-cli -s=x eval "document.querySelector('[data-testid=\"tweetText\"]')?.innerText || document.body.innerText"
```

`-s=x` を必ず指定する（これが無いと別のブラウザに飛び、ログインしていない状態になる）。複数ポストを連続で読む場合は `goto` → `eval` を繰り返す。

## 3. 失敗時

- ログインページにリダイレクトされたら、ユーザーがブラウザを閉じた可能性が高い。1. の手順を再実行して依頼する
- レート制限を疑ったら無理に再試行せず、ユーザーに報告する
- BOT 検知リスクがあるため、短時間の連投・大量アクセスはしない。必要最小限のページだけ取得する
