# 著者の X 告知ポストの書き方

## 本ポストの構成

上から順に並ぶ。3と4は省かれることがある。

1. **1行目は記事の URL だけ**。タイトルは書かず、リンクカードに任せる。
2. **何を書いたかを1文で**。「〜について書きました」「〜を書いてみました」の形が多い。主題は記事タイトルの写しではなく、著者の言葉で短く言い直す。
3. **著者の見方か要旨を1〜2文**。論点が複数ある時は「・」の3項目に分ける。
4. **短い感想を添える**。「楽しかったです」「楽しみにしています」程度の一言。

全体に、記事本文と同じ「です・ます」の平叙で、言い切りを強めない。読者に何かをさせる文で終わらない。

## セルフリプライ

本ポストに自分で返信を続け、裏話を足すことがある。

- 書くのに使ったもの（AI エージェントなど）
- かかった時間や書いた経緯
- 次の予定（英語版を出す、続きを書く等）

本ポストに入れない補足の置き場であり、宣伝を重ねる場ではない。事実は記事・core.md・著者の発言にあるものだけを使う。

## 書く前の宣言ポスト

記事を書き始める前に「〜を書きます（宣言）」と予告することがある。何を書くかを1文で述べ、URL は無い。

## 使わない要素

一般的な SNS の告知の型は著者のポストに無い。次の要素が文案に入っていたら外す。

| 要素 | 例 | 代わりに |
|---|---|---|
| 数字のフック | 「約5ドルで」「1往復1〜2分」を冒頭に置く | 数字は記事に任せる。要旨の中で触れるなら文末側に置く |
| ハッシュタグ | #Tableau #DataFam | 付けない |
| 行動の呼びかけ | 「ぜひ読んでみてください」「試してみてください」 | 感想の一言で終える |
| タイトルの再掲 | 1行目に記事タイトル、「【新記事】」 | URL だけにする |
| 煽り・誇張 | 「必読」「衝撃」「〜の全て」 | 書いたことをそのまま述べる |
| 絵文字・記号の装飾 | 🚀✨📝、「👇」 | 使わない |
| スレッドの型 | 「🧵」「1/5」 | セルフリプライは番号を振らない |

## 良い例と悪い例

架空の記事（BI ツールの運用性の整理）で示す。

悪い例（一般的な告知の型）:

```
【新記事】計算フィールドが100個を超えたワークブックを3割減らした方法
フォルダ整理だけで保守が劇的にラクに🚀
ぜひ読んでみてください！
#Tableau #DataFam
https://example.com/post
```

良い例（著者の型）:

```
https://example.com/post

ワークブックの運用性を上げるための整理について書きました。

・計算フィールドを役割ごとにまとめる
・使っていない計算を消す
・後から読む人の目線で名前を付ける

自分の作業メモを見返す良い機会になりました。
```
