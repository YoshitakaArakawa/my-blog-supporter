# X 告知ポストの文案づくり

`output/{yyyymmdd}_$ARGUMENTS/` の記事を X で告知するポストの文案を、著者の告知の書き方で作る。`$ARGUMENTS` に日付付きのフォルダ名が渡されたらそのまま使う。以降 `$OUTPUT_DIR` はこのフォルダを指す。

告知文は記事の「声」の延長であり、ここでも著者の声と判断を保つ（CLAUDE.md の目的と設計原則）。一般的な SNS マーケティングの型（数字のフック・ハッシュタグ・「ぜひ読んで」）は著者の告知に無く、使うと著者のポストに見えなくなる。

## 規範

- **見本が先、型は後**。毎回、著者の最近の告知ポストを見本として読んでから書く。[references/x-post-style.md](references/x-post-style.md) の型は見本が取れない時の代わりと、見本を読む時の観点として使う。
- **文案は core.md に繋ぐ**。各案に「core.md のどの行（読後・現在地・問い・動機）に効くか」を1行で添える。core.md に無い主張を告知で足さない。
- **言い回しは記事本文から借りる**。core.md の整った言い換えより、著者が本文で使った口語のほうが著者の声に近い。借りた箇所は根拠の行に本文の見出しを添える。
- **著者固有の一言は代筆しない**。感想・裏話の事実（使ったもの・かかった時間・次の予定）は、記事・core.md・著者の発言に根拠がある時だけ書く。根拠が無ければ `{著者の一言}` のような空欄にして著者に戻す。
- **投稿しない**。X の画面での入力・投稿・いいね・リポストなど、閲覧以外の操作をしない。

## 手順

進捗:
- [ ] 1. 記事の確認
- [ ] 2. 見本の取得（著者の承認後）
- [ ] 3. 型の抽出
- [ ] 4. 文案の作成
- [ ] 5. 点検と提示

### 1. 記事の確認

- `$OUTPUT_DIR/core.md` を読む。無ければその旨を伝えて終了する。
- 本文は `published.md` を優先し、無ければ `draft_user.md`、それも無ければ `draft.md` を読む。
- 記事の URL を確かめる。`published.md` 冒頭の取得元、または `/wix-sync` の push で決めた slug（`https://www.yarakawa.com/single-post/{slug}`）を使う。未公開で URL が無い時は `{記事URL}` と空欄にする。

### 2. 見本の取得（著者の承認後）

取得は CLAUDE.md の「Web 取得」に従い、何をどこから取るかを示して著者の承認を得てから行う。

- 対象: 著者の X アカウントの、ブログ記事の告知ポスト（yarakawa.com のリンクを含むもの）を新しい順に5〜8件。告知に続くセルフリプライと、「書きます（宣言）」のポストがあれば併せて読む。
- 探し方: X の検索で `from:{著者のhandle} yarakawa.com` を「最新」タブで開く。handle が分からなければ著者に聞く。
- 既定の手段は Claude in Chrome（著者が普段の Chrome で X にログイン済み）。使う前に `anthropic-skills:chrome-browser` スキルを読む。新しいタブで開き、ページの文字を読むだけにする。
- Chrome に繋がらない時は、著者に最近の告知ポストを2〜3件貼ってもらう。それも無理なら references の型だけで書き、その旨を提示時に明記する。

見本の本文は会話の中だけで使う。リポジトリで追跡されるファイルへ写さない（このリポは Public）。

### 3. 型の抽出

見本を [references/x-post-style.md](references/x-post-style.md) の観点で読み、次を短く書き出す。

- 見本に共通する構成（1行目・書いたことの一文・見方・感想の有無と順序）
- 見本で使われている言い回しと、使われていない要素
- references の記述と食い違う点（食い違ったら見本を優先する）

### 4. 文案の作成

告知の本ポストを2〜3案作る。1案目は既定の型（書いたことの一文 → 問題意識 → 控えめな結論）にする。残りは切り口を変える（例: 現在地を中心にする案／論点を「・」3項目で並べる案）。必要なら、各案にセルフリプライ案を0〜2件付ける。

- 各案の構成は手順3で抽出した型に従う。
- X の上限は重み付きで 280。日本語の文字と全角記号は 2、半角英数・改行は 1、URL は長さに関係なく 23 と数える（日本語だけならおよそ 140 字）。超えたら削る。
- 「書きます（宣言）」を頼まれた時は、本ポストの代わりに宣言ポストを2〜3案作る。根拠は core.md の問い・動機に置く。

### 5. 点検と提示

[references/x-post-style.md](references/x-post-style.md) の「使わない要素」と照らして各案を点検し、該当したら直してから出す。

`$OUTPUT_DIR/x-posts.md` に書き、会話にも同じ内容を出す。形式:

```markdown
# X 告知案: {記事タイトル}

見本: {取得元と件数。取れなかった時はその旨}
抽出した型: {手順3の要約を2〜4行}

## 案A（{切り口}）

{本ポスト}

- 根拠: core.md の {行名}「{その行の要旨}」／借りた言い回し: 本文「{見出し}」
- 字数: {重み付きの字数}/280

### セルフリプライ案

{リプライ。無ければ省く}

## 案B ...
```

どの案を使うか、どこを直すか、投稿するかは著者が決める。
