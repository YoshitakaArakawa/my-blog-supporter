# 認知リズムの設計

## 目次

- 基本原理
- 判定軸：状況更新か、文書更新か
- 文の拍（敬体への翻訳）
- 段落の密度波形
- 緊張の管理（緊張台帳）
- 執筆後の点検手順
- 症状→処方（診断表）

## 基本原理

- 密度の高い文章が退屈になるのは、情報が多いからではなく、全文が同じ認知モードで書かれているから。緩急は情報量の増減ではなく、読者の認知モード（観察する・迷う・確信する・確かめ直す）の切替として設計する。
- 文章は常に、少なくとも1つの「未回収の緊張」（答えの出ていない問い、あとで崩される見込み、あとで返すと置いた答え）を開いておく。緊張がすべて閉じた瞬間、読者は読むのをやめられる。
- 完成した結論を解説する声ではなく、考えながら進む当事者の声で書く。書き手が答えに至る過程の再演が、読者の思考の再演になる。

### 真正性ガード（本リポでの最上位制約）

- 拍・緊張・逡巡の材料は、brief.md / thinking.md / references.md に記録された著者の実際の体験・判断・データからのみ取る。演出のために思い込み・迷い・転回を捏造しない（CLAUDE.md「真正性 > 網羅」「無根拠に足さない」の適用）。
- 材料が見つからない位置は、平坦なまま残す。リズムのために埋めた偽の逡巡は、空欄より悪い。
- 一次感情など AI が材料を持たない緊張は、✍️ マーカーで著者に戻す（write の手順に従う）。

### 装置は宣言せず、内容で実現する

- この規範の語彙・操作名（「緊張」「回収」「拍」「答えの半分」等）を draft.md 本文にそのまま書かない。問いを半分ずつ返す操作は、答えの前半を内容として書くことで実現する。
- これからやる操作の宣言（「先に結論を置きます」「最後にもう一度整理します」）は、それ自体が削除対象。装置が機能していれば、読者は装置の存在に気づかない。

## 判定軸：状況更新か、文書更新か

緩み（残してよい停止・脱線）と駄文（削るべき文）の判定軸は1つだけ。その文が更新するのは「状況」か「文書」か。

- 状況を更新する文：対象世界の出来事・データ・発言、または書き手の判断の状態（見込み・保留・後悔・譲歩・告白）を新しく伝える。→ 緩みとして残してよい。
- 文書を更新する文：この記事・この章・ここまでの話が「どう見えるか」「次に何を書くか」だけを伝える。→ 原則削除する。

voice-style ルール22の空句リスト（「本記事では〜を扱う」「まとめると」等）は、すべてこの軸の具体例。リストに無い形でも、話題が本文自身なら削る。

最大の混入経路：文書更新の文を短い言い切りに整形すると、決め台詞に見えて残りやすい。短くてリズムが良いことは、残す理由にならない。拍の評価は、この判定を通過した文についてだけ行う。

### 例外として残せる形

1. 反論処理：読者の誤読・反論を「」で具体的に引用して退ける。漠然と「誤解しないでほしい」だけの文は削る。
2. 問いの設置と回収：緊張を作ったあとの「この記事で考えたいのは〜です」と、回収の文。本文が「何でないか」の宣言（「〜の話ではありません」）は問いの設置ではない。
3. 読者への依頼・断り：「どうか〜と割り切って読んでください」型。冒頭・結びの境界に限る。
4. 例の枠の開閉：「〜としましょう」で架空の場面を開き、「冒頭の例に戻ります」で閉じる文。

注意：読者への問いかけ（「〜ですよね？」「〜な気がしませんか」）は voice-style ルール4の文体資産であり、本文中盤でも使ってよい。境界に限定するのは 3 の「依頼・断り・謙抑」だけ。

## 文の拍（敬体への翻訳）

原規範の「断定と逡巡の交互配置」を、著者の敬体・ヘッジ文体ではこう読み替える。

- 逡巡 ＝ 著者のヘッジ（「〜と思います」「〜な気がします」「〜かもしれません」）。文体資産なので削らない。
- 断定 ＝ ヘッジなしの言い切り（「〜です」「〜でした」）。検証済みの事実・確定した出来事・自分の決断は言い切る。「絶対」「必ず」の強断定は不要（ルール2と両立）。
- 平坦化の正体は、同型のヘッジ語尾の連続（ルール1「3-4文連続で AI 的」と同じ現象を、リズムの側から言ったもの）。ヘッジ文の間に、言い切り・具体的事実・問いかけを挟んで拍を作る。
- 「立てる→流す→止める」を段落の基本拍にする。短文で足場を打ち、長めの文で展開し、短文で止める。長い文が3つ以上続いたら、短い言い切りか問いを挟む。
- あとで崩される見込み（「うまくいくと思っていました」→「記録を見ると、そうではありませんでした」）は強い布石になるが、thinking.md に実際の見込み違い・修正の記録がある時だけ使う（真正性ガード）。

## 段落の密度波形

- 密な段落（具体・論証）が2〜3個続いたら、疎の段落を1つ置く。疎の機能は次の3つに限る：確定事項の一行固定、次に確かめることの提示、視点距離の切替。
- 視点の距離を固定しない。具体（記録・数値・発言・固有名詞）に寄る段落と、意味づけで一段引く段落を交互に置く（ルール5「具体観察→抽象解釈」の交互反復）。
- 箇条書きは情報の圧縮であると同時に、本文の呼吸を止める「間」でもある。列挙は列挙しっぱなしにせず、各項目を直前の具体的な場面・体験へ着地させる。着地の文体は均一にしない。

## 緊張の管理（緊張台帳）

- 本文中で立てた問い・見込み・約束を列挙し、それぞれの回収位置を行で指せるか確認する。指せないものは、回収を書き足すか、問いごと削る。
- 導入で予告した論点・具体例が本文で回収されているかの確認（write 手順3「導入の事後確認」）は、この台帳の導入部分にあたる。
- 緊張は選んで閉じる。結びに1つだけ開いたまま残してよい。答えの出ない問いを正直に残す結び（ルール9の問いかけ型・割り切り型、ルール23）は、緊張の意図的な残置として機能する。
- 節と節の橋は、前節の末尾ではなく次節の頭に置く。前節末尾の「次は〜を見ます」型の予告は文書更新文（ルール6のロードマップ禁止と同じ）。次節の頭が問い・違和感・具体で開けば、予告がなくても読者は続けて読む。

## 執筆後の点検手順

draft.md を書き上げたら、次の順で機械的に点検する。

1. 話題テスト：段落の頭の文と独立した短文をすべて拾い、状況更新か文書更新かを判定する。文書側は例外4形に該当しない限り、削除するか状況側の文へ書き換える。推敲で新しく書いた文・短く割り直した文は混入経路なので、書いた直後にも判定にかける。
2. 漏出テスト：この規範の語彙（「緊張」「回収」「拍」「答えの半分」等）が本文にそのまま現れていないか検索する。あわせて、全節末に進行予告がないか確認する。
3. 緊張台帳：立てた問い・見込み・約束を列挙し、回収位置を指す。指せないものは回収を足すか削る。意図的に残す問いは1つまで。
4. 拍の点検：同型のヘッジ語尾、または長い文が3つ以上連続する箇所を探し、言い切り・短文・問いかけを挟む。
5. 境界の点検：読者への依頼・断り・謙抑が本文中盤にないか確認する。あれば境界へ移すか削る（問いかけは中盤でも可）。

## 症状→処方（診断表）

平坦な原稿を診断するとき（/review-author-draft のリズム観点を含む）は、症状から処方を引く。

| 症状 | 原因 | 処方 |
|---|---|---|
| 全段落が同じ調子で疲れる | 拍がない | 点検手順4。同型語尾・長文の連続を割る |
| 規約違反は無いのに読み進める気がしない | 未回収の緊張がない | 冒頭で緊張を1つ作り、台帳で常に1つ開いていることを確認する |
| 概念説明の章で急に温度が下がる | 概念が違和感より先に出ている | 概念の前に問い・具体的な引っかかりを置く。列挙は場面へ着地させる |
| 緩い文はあるのに弛んで見える | 緩みが文書更新（進行実況）になっている | 話題テストにかけ、状況側（判断の保留・見込み・感情の微差）へ書き換える |
| 結びが説教くさい | 抽象論のまま閉じている | 読者がすでに持つ具体（冒頭の体験・序盤の問い）へ着地させてから閉じる |
| 冒頭が事務的 | 態度のない議題表になっている | 削らず、宣言に態度を与えるか、前に体験・動機を置く（ルール19） |
