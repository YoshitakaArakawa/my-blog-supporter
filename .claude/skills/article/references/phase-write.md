# 書く工程

## 目次

- 前提
- 入力
- 0. 層と章の設計（著者の承認）
- 1. 執筆
- 2. 機械 lint
- 3. 自己レビュー
- 4. 隔離レビュー（readers と drift）
- 指摘反映の採否基準（主題か、鎧か）
- 5. 著者への提示と磨きこみ
- 6. 完了

## 前提

- Node.js と `npm install` 済みであること（機械 lint が textlint を使う）。未導入なら lint は「textlint が未導入です」と返すので、数値仕様の判定だけで進めてよい
- 文体の正本は `voice-style.md`。**0. 数値仕様と 1. 実例を先に読む**。ルールは実例で伝わらない判断を補うもの

## 入力

- `$OUTPUT_DIR/core.md`（必須。無ければ核の工程へ戻す）
- `$OUTPUT_DIR/thinking.md`（各セクションで展開する主張・素材）
- `$OUTPUT_DIR/outline.md`（あれば。見出し構成・展開順序・資料接続の設計図）
- `$OUTPUT_DIR/references.md`（あれば。参考リンクを本文中に配置するため）
- `voice-style.md`（必須）
- `cognitive-rhythm.md`（必須。認知リズム＝緩急の設計規範。緊張・拍・密度波形と点検手順）

## 0. 層と章の設計（著者の承認）

draft.md を書き始める前に、章の設計を1つの表で著者に見せ、承認を取る。outline.md がある時はその章立てを表に写し、無い時はここで初めて章を決める。outline.md を省いた時ほど必要で、省くと構成の作り直しが磨きこみの主因になる。

| 章 | 読者に渡すもの | 前章との因果（なぜこの順か） | 素材の粒度 |
|---|---|---|---|
| {見出し案} | {読み終えた時に読者が得るもの1つ} | {前章の何を受けてこの章が要るか} | 価値 / 過程 / 一次記録 |

- 素材の粒度は3段で決める。**価値**（最終形として何が起きるか）、**過程**（どう進めたか、何を足したか）、**一次記録**（作業ログの番号・個数・道具名）。価値を語る章に過程と一次記録を混ぜない。一次記録は本文に出さず、意味に言い換える（voice-style ルール21）
- 章の順は thinking.md の深掘りリストの順にしない。読者が追える因果で並べ、表の「前章との因果」欄が埋まらない章は置き場所を考え直す
- 同じ章に並べる項目は同じ種類にする。独立した話（例: 道具に足したものと、確認の仕組みを作ったこと）を同列に並べない。別の章に切る
- まとめの図は、その図が回収する話をすべて語った後に置く。回収の前に出すと読者は図の意味を持てない
- 核の「現在地」「読後」は段落ではなく章で担う（核カバレッジ表は手順3）

承認が取れたら表を draft.md 冒頭の ℹ️ メモ（著者判断）に写し、以降の構成変更はこの表を更新してから本文に入れる。

## 1. 執筆

voice-style.md に従い、Markdown で記事本文を `$OUTPUT_DIR/draft.md` に書く。

- 手順0で承認された章の設計に沿い、各章を thinking.md の主張・素材で肉付けする。outline.md があればその展開順序・資料接続も使う
- **冒頭は宣言スタートが既定**（voice-style ルール19）。「この記事では〜について書きます」＋スコープ 1〜3 文＋執筆動機 1〜2 文。参加記だけ体験スタート。参考資料ブロック・固定ヘッダ・著者プロフィールは書かない
- 段落は 1〜2 文。事実・年表・並列は箇条書き、思考は散文（ルール11）
- 段落は論点のまとまりで組む（voice-style 実例8、ルール11「段落のまとまり」）。「1〜2 文」は、短文を1行ずつ改行して満たさない
- 節は観察か分解から入る。想定反論（「〜で足りるのでは」）を節の入口に置かない。反論への答えは分解の中で自然に処理し、反論を否定する形の文（「〜とは考えていません」「〜という理由は使いません」）を立てない
- 章の分量は outline.md の目安字数に合わせる。lint の「章ごとの字数」が目安の 8 割を下回る章は、thinking.md と references の素材（著者の発言・体験・調査結果）で加筆する。素材が無い箇所を AI の一般論で埋めず、✍️ で著者に戻す
- 緩急は cognitive-rhythm.md に従い、認知モードの切替として設計する。緊張・逡巡の材料は core.md / thinking.md / references.md の実素材からのみ取り、材料が無い位置は平坦なまま残す（真正性ガード）
- 参考リンクは本文中の該当箇所に短い導入＋タイトルの箇条書きで分散させる
- 図は章ごとに検討する。対比・層・段階・流れのように、関係が文章だけでは伝わりにくい箇所に `<!-- 画像: {何と何の、どんな関係を示す図か} -->` を置く。一次素材のスクリーンショットがあればそれを優先する。事実の羅列や余談には置かない。作図は著者の承認後に `/illustrate` へ渡す。作図が済んだら、`/illustrate` が返す `![{キャプション}](images/{図名}.png)` の1行でプレースホルダーを置き換える（プレビューに図が出る）
- **✍️ 可視マーカーは AI が一次情報を持たない箇所だけ**。特定の瞬間の一次感情・私的体験など core.md / thinking.md から確認できない素材を、引用ブロック `> ✍️ ここに〇〇を一次感情で（仮置きは過去記事ベース、著者が上書き）` として残す。導入の執筆動機は ✍️ にせず AI が書く
- **ℹ️ 引き継ぎメモ**をドラフト冒頭に引用ブロックで置く。本文に入れなかった反論への返し・出典の性質・削った保険文を「コメント欄で突かれたら返す用」として列挙する。本文には出さない
- ℹ️ メモの先頭には、次の2つを置く。セッションを区切っても、ファイルだけで再開できるようにするため
  - 書く工程の進捗: この手順0〜6のチェックリスト。手順を終えるたびに [x] と日付に更新する
  - 著者判断: 会話でだけ決まったこと（手順0で承認された章の設計、字数の方針、構成上の例外、書かないと決めたこと）

## 2. 機械 lint

```
node scripts/lint-draft.mjs $OUTPUT_DIR/draft.md
```

- NG がゼロになるまで直して再実行する（最大 3 周）。数値仕様・禁止句・冒頭／結びの型・textlint の error を対象にする
- 直さない判断をした項目は、理由を ℹ️ メモに 1 行で残す（例: 「英文引用 4 文: dbt 原文が主題のため維持」）
- PostToolUse hook が設定されていれば、以降の Edit/Write のたびにレポートが自動で返る。同じファイルの2回目以降は前回との差分（NG の増減・新しい禁止句の行）だけが返り、変化が無ければ1行になる。全文が要る時は手動で実行する

## 3. 自己レビュー

lint では見えないものだけを読み返す（voice-style「生成後の点検」の 2）。

- 実例 2〜4・9 の手触りに近いか（反論を認めたまま次へ進んでいるか、引用素材を 1 段で渡しているか、読者の困りごとから入っているか）。著者の口癖（「まぁ」「...」「！」）を AI が足して似せていないか
- 論理の飛躍: 読者が「なぜ急にこの話に？」と感じる箇所
- **核カバレッジ表**: core.md の5行それぞれに、それを担う章の見出しを書く。書けない行があれば、段落の付け足しではなく章を立てる。「現在地」と「読後」が章末の一段落に押し込まれている形は、この表で見つける

  | 核の行 | 担う章 |
  |---|---|
  | 問い | {見出し} |
  | 読者 | {見出し} |
  | 読後 | {見出し} |
  | 動機 | {見出し} |
  | 現在地 | {見出し} |

- 抽象度の天井: 一次記録の番号・個数・道具名・モデル名が本文に残っていないか（voice-style ルール21。lint の「一次記録由来の識別子」も見る）
- 分量と図: lint の「章ごとの字数」を outline.md の目安と比べる。図のプレースホルダーが、関係を示すべき要所に置かれているか
- 図のラベルと本文の語が一致しているか。本文の語を変えたら図も追随させる（`/illustrate` で同名上書き）
- 見出しが節のオチを言い切っていないか、批判の向きが我々ユーザー側か、固有名詞が抽象化されていないか
- **認知リズム**: cognitive-rhythm.md の「執筆後の点検手順」（話題テスト・漏出テスト・緊張台帳・拍・境界）を順に実行する。緊張台帳（立てた問いの回収位置）は次の導入の事後確認 (a) と重なるので併せて行う
- **導入の事後確認**: 本文を確定させた後に導入を読み直す。(a) 予告した論点が本文で回収されているか、(b) 執筆動機が本文の主張・結論と整合しているか、(c) 導入で挙げた具体例が本文で展開されているか。ズレていれば導入を直す

## 4. 隔離レビュー（readers と drift）

どちらも書く工程の既定。本文が生成された後の点検はコストに見合う。

1. `Skill` ツールで `review` を lens `readers` で起動する。初見の読者視点（core.md の「読者」「読後」＋懐疑側・前向き側）での離脱点・反応・行動変化・炎上経路の予測を得る
2. `Skill` ツールで `review` を lens `drift`、対象 `draft` で起動する。前段からの背骨落ち・無根拠 add が無いことを確認する

レビューが「条件を戻せ」「留保を足せ」「前提を明示せよ」と言った項目は、AI が本文に反映しない。著者に採否を渡す（下の採否基準）。

## 指摘反映の採否基準（主題か、鎧か）

自己レビュー・readers・drift の指摘を反映する時は、修正ごとに「この修正は記事の主題を深めるか、想定反論への鎧を増やすだけか」を問う。

- **主題を深める修正** → 本文に反映する。例: 自己矛盾を隠さず明示することは、誠実さを主題とする記事ではそのまま主題の実演になる
- **鎧を増やすだけの修正**（想定反論の先回り潰し・括弧書きの防御ヘッジ・補足条件の列挙）→ 本文に入れず ℹ️ メモに残す。大域のヘッジ（「保証できない」の一文）に論理的に包含される個別の先回りは足さない
- **条件・限定・留保の追加**（「〜が揃えば」「この実験に限った話」「〜は確かめていない」）→ レビュー由来であっても AI は本文に足さない。候補として著者に渡し、著者が選んだものだけ入れる。本文に置く限定は記事全体で1つを目安にし、残りは ℹ️ メモへ。隔離レビューは前段の条件を忠実に戻そうとするため、鎧の供給源になりやすい

反映後に手順2の lint を再実行する。

## 5. 著者への提示と磨きこみ

- 著者が読むのはプレビュー `$OUTPUT_DIR/preview/index.html`。ℹ️ メモを落とし、図とプレースホルダーを配置した見た目で出る。正本は draft.md なので、直しは draft.md に入れ、HTML は編集しない（次の生成で上書きされる）
- 全文を一度に出さず、「全体の流れ」「lint の残件と直さなかった理由」「特にフィードバックがほしい箇所」「図の一覧（章と、何を示す図か）」を添える
- 初回の提示を終えたら、新しいセッションで磨きこみを続けるかを提案し、引き継ぎプロンプトを出す（SKILL.md「セッションの区切り」）
- 構成上の判断（なぜこの順序にしたか）があれば簡潔に説明する
- フィードバックの反映 → lint → 再提示、を著者が満足するまで繰り返す。反映で本文が膨らんだら、保険文・章間の道案内・多段論証の順に自分で削る（voice-style ルール22・23）
- **構成の議論は全文で、文の直しは差分で**。章の切り直し・順序の入れ替え・層の分け直しのような構成の変更は、draft.md を直接書き換えず、`$OUTPUT_DIR/experiments/{案名}.md` に全文を組み直して書き、`node scripts/render-preview.mjs $OUTPUT_DIR/experiments/{案名}.md --out $OUTPUT_DIR/experiments/{案名}.html` で HTML にして見せる（図のパスは `../images/` で書く）。差分表示は出さない。著者は「文章全体がどう変わるか」を見て判断する。採用が決まったら draft.md に反映し、手順0の表を更新する。文単位の直しは `/revise` の差分で見せる
- **同じ章で磨きこみが3周を超えたら、素材から白紙で書き直す**。細かい修正の積み重ねは全体感を失わせる。既存の draft.md を見ずに、core.md・thinking.md・references.md と手順0の表から experiments/ に書き直し、現行版と並べて著者に選んでもらう
- 著者が提示した文章・見出しは原文どおり入れる。lint に触れても直さず、ℹ️ メモの lint 節に「著者原文」と理由を書く。見出しの型の警告も同じ扱いで、著者の見出しを型に合わせて直さない
- 著者が清書（Wix への書き起こし）を始めていたら、変更提案は章ごとに分け、清書済みの章への変更は別枠で明示する

## 6. 完了

- 「`$OUTPUT_DIR/draft.md` に最終版を保存しました」と伝える
- Wix への書き起こし方を著者に選んでもらう。図が必要なら先に `/illustrate` へ渡す
  - `/wix-sync` で draft.md を画像込みの下書きとして流し込む（著者の承認後）。AI の文が初期値になるので、Wix 上で自分の言葉で書き直す下地であることを添える。未作図のプレースホルダーは `［画像（未作図）: …］` の段落で入る
  - 手で書き起こす。「図（`![...](images/...)`）は画像をアップロードし、画像プレースホルダー（`<!-- 画像: ... -->`）は実際の画像に差し替えてください」と伝える
- 空の `$OUTPUT_DIR/draft_user.md` を生成する（既に存在する場合はスキップ）。「ユーザー推敲版用に `draft_user.md` を空白で作成しました。AI 版を参考にしながら、ご自身の言葉で書き直したり、独自の構成で書いたりしてください」。Wix で書く場合は、`/wix-sync` の pull がここへ Wix の下書きを取り込む
- 磨きこみで著者が同じ方向に繰り返し直した箇所（語尾・保険文・章の切り方など）があれば、voice-style.md への反映を進行の確認として1問で提案する。承認された項目だけを編集し、閾値を変えた時は `scripts/draft-lint.config.json` も同期させる
