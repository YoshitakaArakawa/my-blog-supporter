# 掘る工程

## 目次

- 入力
- 1. スコープの確定
- 「本質的」＝深掘りする価値がある、の判定
- 2. 深掘りの対話
- 3. コアメッセージの磨きこみ
- 4. thinking.md の生成・更新
- 5. 未決の整理と次の一手
- やらないこと

考察・思索の共有が記事の主軸であるため、論理検証よりも **思考を揺さぶり、新しい気づきを引き出す**ことを重視する。ただし深掘りは無制限ではない。記事の本筋に効く本質的な論点に絞って厚くするのがこの工程で、論点を増やして分量を膨らませる工程ではない。何を深掘りするかはスコープの確定で先に絞る。自由度は高く保つ（対話が本質）が、狙いは絞る。

## 入力

- `$OUTPUT_DIR/core.md`（必須）。「問い」「読者」「読後」は深さの境界として読む。何を掘るかだけでなく、**何を掘らないか**の基準にする
- `$OUTPUT_DIR/thinking.md`（あれば。2周目以降。前回どこまで掘ったかを把握する）
- `$OUTPUT_DIR/references.md`（あれば。概要レベルで対話に活かす）
- `$OUTPUT_DIR/references/` の raw 資料（あれば。PDF・画像・テキストは Read で読める）
- `$OUTPUT_DIR/review/critique_*.md` の最新（あれば。前回の指摘を今回の深掘りの起点にする）

## 1. スコープの確定

深掘りに入る前に狙いを絞る。これを飛ばすと本筋から外れた論点を掘り、分量が膨らむ。

1. **横に広げる**。「何がありそうか」を幅広く出す対話を先に置く。各項目を深掘りせず、「他にはどんな観点がありそうですか」と広げる方を優先する。ここで拾うもの: 観点の候補、使えそうな具体・エピソード、参考資料や過去記事との関連、読者が持ちそうな反論、カテゴリ（GenAI × Tableau、データ可視化コラム、Tableau スキルアップ 等）
2. **本筋を提案する**。core.md の「問い」から、記事の通底メッセージを1文で提案する。決めるのは著者
3. **読者が興味を持ちそうなトピックを2〜3個提案する**
4. 著者が確認・修正する。**1往復に留める**（質問票にしない。自由度を殺さない）
5. 確定した狙いから **深掘りリストを3〜5点に絞る**。下の4条件で取捨する。5点を超えそうなら本質を問い直して削る。分量は深さ×点数で決まるため、点数の規律が分量を守る
6. 各点に、効く core 行（問い／読者／読後／動機／現在地）を付す

## 「本質的」＝深掘りする価値がある、の判定

ある論点は、次を **すべて満たす時だけ** 深掘りリストに入れる。

1. **コアメッセージ依存**: 言語化しないとコアメッセージが崩れる／弱る
2. **読者のつまずき or 関心**: 読者が「なぜ？」「本当に？」と引っかかる、または興味を持つ
3. **一文では足りない**: 本文で1文の防御線では処理できず、厚い言語化が要る
4. **著者固有性**: 一般論でなく著者だから書ける（体験・立場・具体）。AI が一般論で埋まるなら深掘り不要

**退避のシグナル**: 思弁的・将来予測で検証不能／結びのトーンしか変えない／読者の前提を超える専門度／コアメッセージ無しでも成立する周辺／一般論または一文で足りる。該当する論点は thinking.md の「駐車場」へ退避し、深掘りしない。

この4条件は、隔離レビューの critique から戻った指摘の採否にも当てる。指摘が4条件を満たさなければ駐車場へ送る。

## 2. 深掘りの対話

深掘りリストの観点（書く動機を含む）を一つずつ取り上げ、言語化を厚くする。critique の指摘がある場合は、その論点を優先的に掘り直す。

**やること**:

- 各観点について「具体的にはどういう意味か」「なぜそう考えるか」を掘り下げる
- 書く動機そのものも観点の一つとして掘る（「なぜ今これを書きたいのか」を一歩踏み込んで問い直す）
- 参考資料の内容と著者の考えの接続・差異を明確にする
- 曖昧な表現を具体化する
- 具体的なエピソードや体験を引き出す（記事の素材になる）

**問いの例**:

- 「この観点について、もう少し具体的に言うと？」
- 「なぜ今これを書きたいのか、一歩踏み込むと何が動機ですか？」
- 「参考資料の○○という主張と、あなたの考えはどう違いますか？」
- 「読者がここで引っかかるとしたら、どこでしょう？」
- 「この考えを一言で表すと何ですか？」
- 「逆の立場の人はどう反論しそうですか？」
- 「もし○○だったら、この考えは変わりますか？」

**対話のガイドライン**:

- 著者の言葉を引き出すことが目的。AI の意見を押し付けない
- 問いの数は制限しない。必要な問いはまとめて出す。ただし観点は一つずつ掘り切ってから次へ移る（問いを並べても、掘る対象は散らさない）
- core.md の「読者」「読後」に効くポイントを掘る。著者が面白がっても読者に不要な論点は掘らず、駐車場へ退避する
- 対話が深掘りリストの外へ逸れたら、4条件で退避を判断し、著者に「この論点は今回必要か」を一言確認する（深さの停止条件）
- 論理の飛躍があれば指摘するが、あくまで対話的に。本格的な批判は隔離レビューの critique に委ねる
- 主張の裏付けに事実確認が要ると分かったら、その場で調べずに著者へ提案する。承認後に取得し、結果は references.md に1行、raw は `$OUTPUT_DIR/references/` へ

## 3. コアメッセージの磨きこみ

対話で見えてきたことを踏まえ、コアメッセージを明確な表現にする。core.md の「読後」行を踏み台にして、「この記事を読んだ人が読後にどうなっていてほしいか」を言語化する。

core.md の「問い」と矛盾するコアメッセージになったら、言い換えて丸めず、著者に「核を変えるか」を聞く。

## 4. thinking.md の生成・更新

対話の成果を `$OUTPUT_DIR/thinking.md` に書く。既にあれば最新の到達点に更新する（最新が正）。記事の見出し構成はここに書かない。

provenance タグを付ける: `[著者]`（著者の発言由来）／`[著者X]`（X ポスト等の著者の既存発言）／`[AI整理]`（AI が言い換え・構造化した箇所）／`[AI案・要確認]`（AI が仮置きし、著者の確認が要る箇所）。

字数の上限は置かない。分量は深掘りリストの点数と未決の件数で守り、字数のために著者の発言や素材を削らない。

```markdown
# 思考の深掘り: {記事タイトル案}

## スコープ
- 本筋（1文）: {記事の通底メッセージ}
- 深掘りリスト（3〜5点。各点に効く core 行を付す）
  - {論点1} — 効く核: {問い|読者|読後|動機|現在地}
  - {論点2} — 効く核: {…}

## コアメッセージ
{対話を通じて明確になったコアメッセージ}

## 各観点
### {観点1}
- 主張: {具体的にどういうことか} [著者]
- 根拠・背景: {なぜそう考えるか}
- 素材: {この観点で使う具体例・エピソード・資料}

### {観点2}
...

## 駐車場
- {今回掘らない論点・core に効かない問い・別記事候補。1行ずつ}
- {隔離レビューから戻ったが採らなかった指摘も、1行で理由を添えてここへ}

## 素材
- {記事に使える具体・エピソード・数字・引用。出典があれば references.md の行を指す}
- {対話で著者自身の言葉で出た印象的なフレーズ}

## 未決
- {著者に返す問い。核への効き順} — 効く核: {問い|読者|読後|動機|現在地}
```

新たに出てきた参考情報があれば `$OUTPUT_DIR/references.md` に追記する。事実確認の結果は1行で書き、thinking.md に「裏取り」「調査結果」の節を作らない。

## 5. 未決の整理と次の一手

thinking.md を更新したら、未決を核への効き順に並べる。効く core 行を名指しできない問いは駐車場へ移し、著者に出さない。

掘る対話がひと段落したら、地図を更新する（SKILL.md「地図の更新」）。そのうえで著者に返すのは次の3つだけ。

1. 更新した thinking.md のパスと、今回厚くなった論点の見出し
2. 未決の問い（核への効き順。必要な分をまとめて。各問いの文末に効く核を添える）
3. 「主張を叩いておきますか」の提案（critique は著者が頷いた時だけ呼ぶ）

## やらないこと

- 記事の見出し構成を設計する（組む工程の担当）
- critique を自動で走らせる、AI が critique の指摘に自答してループを回す
- 著者固有の論点を AI の一般論で埋める
- 想定反論の先回りを本文に積む（駐車場へ送る）
