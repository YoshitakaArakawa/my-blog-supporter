# 地図の仕様

## 目次

- 守る規範
- 1. 入力の読み込み
- 2. 抽出
- 3. 生成
- 4. 検算
- 5. 著者へ返すもの

core.md も thinking.md も outline.md も読み下す形式であり、章と章の関係・軸の射程・落とした論点・まだ埋まっていない箇所が同時に視界に入らない。地図はその1点だけを解く。

## 守る規範

1. **レンダリングに徹する**。分析・評価・改善提案を HTML に書かない。書けるのは、入力ファイルに既にある内容の写像だけ。良し悪しの判断は著者が下す
2. **正本を二重化しない**。正本は Markdown（core.md / thinking.md / outline.md）。HTML は一方向の写像であり、著者が HTML を手で直すと乖離する。変更は Markdown 側に入れて再生成する。この旨をフッタに明記する
3. **推測で埋めない**。入力に無い箇所は `未定` として表示する。**埋まっていない箇所が見えること自体が、この地図の価値の半分**
4. **テンプレートとスクリプトを改変しない**。`templates/map-template.html` の構造とトークン、`scripts/render-map.mjs` のレンダリングロジックはそのまま使う。記事間で見た目を揃え、浮いた時間は中身の写し取りに使う
5. **出力は output/ に置く**。`published/` へは持ち出さない
6. **上書きする**。`map.html` は最新が正。世代を `map_NN.html` として溜めない

## 1. 入力の読み込み

`$OUTPUT_DIR` から読む。core.md 以外はすべて「あれば読む」であり、揃っていなくても中断しない。

| ファイル | 地図のどこに写るか |
|---|---|
| `core.md` | 核の5行（ヘッダ直下）、thesis、読者、Questions の土台 |
| `thinking.md` | 各章の主張、貫く軸、未決の問い、駐車場 |
| `outline.md` | 章の順序、見出し、分量配分、素材の接続 |
| `references.md` | 各章の素材の出典表示 |
| `draft.md` | ヘッダ meta の本文字数（あれば） |

`core.md` が無い場合は地図を作らず、核の工程で core.md を先に作る。`thinking.md` も `outline.md` も無い時は、核の5行と `未定` だけの地図になる。それでも描く（何が埋まっていないかが見える）。

`outline.md` が無い場合、章の行は thinking.md の「各観点」の並びで代替し、順序が未確定である旨をヘッダの meta に明示する。

## 2. 抽出

入力から次の8つを取り出す。**それぞれ、どの入力ファイルのどの記述に対応するかを言えること**を条件にする。言えないものは書かない。

1. **核**: core.md の5行（問い／読者／読後／動機／現在地）をそのまま写す。要約・言い換えをしない
2. **主題（thesis）**: この記事の一番伝えたい一文。thinking.md のコアメッセージ、無ければ core.md の「問い」から採る
3. **章**: 順序・見出し・想定分量。分量はゲージの相対値になるので、最大の章を 100% として比率を出す
4. **章ごとの3層**: 主張（その章で立てる一文）／論点（扱う論点のラベルと、扱い方の注意）／素材（使う具体・エピソード・資料と、その出典ファイル名）
5. **貫く軸**: 複数の章をまたいで走るもの（通奏する問い、用語の定義、判定軸、一次素材）。開始章と終了章を持つ
6. **記事が答える問い**: 読者が持ち込む問いと、記事が返す答え、返す章
7. **未決の問い**: thinking.md の「未決」節。各問いに、効く core 行（問い／読者／読後／動機／現在地）を添える
8. **扱わないこと**: 意図的に外した領域と行き先（別記事・既刊・短く済ませる・書かない）、および thinking.md の「駐車場」の各行。駐車場の行は `駐車場` のラベルを付けて同じ区画に並べる

重心（最も重い章）が特定できるなら1つだけ `hot` として強調する。複数を強調しない。重心が読み取れないなら強調しない。

## 3. 生成

抽出結果を `$OUTPUT_DIR/map.json` に書き、スクリプトでレンダリングする。HTML を直接書かない。

```
node scripts/render-map.mjs $OUTPUT_DIR/map.json
```

`--out` 省略時は `map.json` と同じディレクトリの `map.html` に書き出す。テンプレートは既定で `templates/map-template.html` を使う（変更しない。守る規範4）。

map.json のスキーマ（キー一覧・各キーが8項目のどれに対応するか・章数0件のときの扱い）は `scripts/render-map.mjs` 冒頭のコメントを参照する。要点だけ挙げる。

- トップレベルは `meta` / `core` / `thesis` / `mapLede` / `chapters` / `threads` / `questions` / `openQuestions` / `boundaries` / `canonicalFiles` の10キー。すべて必須（値は `null` や空配列でよい）
- `core` は core.md の5行（`question` `reader` `afterRead` `motivation` `whereNow`）をそのまま写す。要約・言い換えをしない
- `chapters` の各要素は章ごとの3層（`claim` 主張／`issues` 論点／`materials` 素材）を持つ。値が無い層は `null` にする（スクリプトが `未定` として描画する。規範3を自分で書かなくてよい）
- `threads`（貫く軸）は `start` / `end` に章のインデックス（1始まり、`chapters` の並び順）を指定する。グリッド上の帯の位置はスクリプトが計算する
- 章数がテンプレートの列数と違っても、グリッドの列数はスクリプトが自動で合わせる。手で `grid-template-columns` を触らない

必須キーが1つでも欠けていると、スクリプトはどのキーが無いかを表示して終了する（exit 1）。表示されたキーを map.json に足して再実行する。

Artifact ツールが使える環境では、書き出した map.html を private Artifact として公開する。**同じファイルパスで再デプロイして URL を固定する**（記事ごとに1つの URL）。

## 4. 検算

書き出した後に確認する。1つでも満たさなければ直してから次へ進む。

- map.json のすべての記述が、入力ファイルのどこかに対応しているか。対応を言えない記述が1つでもあれば削る（規範3）
- 核の5行が core.md の文言そのままか。言い換えていないか（不変条件1）
- 埋まらなかった箇所が `未定` として可視化されているか。黙って省略していないか（閉じタグの対応はスクリプトが保証するので確認不要）

## 5. 著者へ返すもの

**「地図: {URL またはパス}」と変更点1〜2行だけ**。地図の内容を会話に貼らない。規模の内訳や `未定` の一覧を並べない（地図を見れば分かる）。

書き始める前の合意ゲートとして使う時だけ、問いを1つ添える。「この重心でよいか」「外した領域はこれでよいか」「`未定` を埋めてから書き始めるか」のうち、最も core に効くもの1つ。AI が地図を作って AI が承認する形にしない。
