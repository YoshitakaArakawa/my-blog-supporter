## 前提：縮小表示

図はブログ本文幅（約 720px）に縮小して表示される。キャンバス幅 1180 の図は約 0.6 倍で見られる。

このファイルの数値はキャンバス幅 1180 換算で書く。幅が違えば比例させる（例: 幅 1500 なら各値を 1500/1180 倍）。

## 配色

パレットは次の表から選ぶ。表に無い色は使わない。1枚の図で使う有彩色は主強調＋第2強調の2色までで、残りはニュートラルで組む。

| 役割 | HEX | 使いどころ | 背景に対する比 |
|---|---|---|---|
| 背景 | `#fbfbfa` | キャンバス全面 | — |
| 墨（読ませる文字） | `#1b2430` | 見出し・主ラベル・塗りの無い場所の文字 | 15.1:1 |
| 補助文字 | `#5c6670` | 注記・副題・凡例・出典 | 5.7:1 |
| 主強調 | `#2f6f6b` | 主役の塗り・枠線・矢印。白文字を載せてよい（5.8:1） | 5.6:1 |
| 主強調（文字用） | `#215e5a` | 背景の上に主強調色で文字を置く時 | 7.2:1 |
| 主強調の淡色 | `#f1f6f5` | 主役側の領域の下地。上の文字は墨か補助文字 | — |
| 濃色の面 | `#26404a` | 基盤・土台など「支える側」の帯。白文字を載せる（11.0:1） | 10.6:1 |
| 第2強調 | `#b85a2a` | 主役と対になる相手の塗り・枠線。白文字を載せてよい（4.6:1） | 4.5:1 |
| 第2強調（文字用） | `#9c4a23` | 背景の上に第2強調色で文字を置く時 | 5.9:1 |
| 第2強調の淡色 | `#fdf3ea` | 相手側の領域の下地 | — |
| ニュートラルの面 | `#eaeef1` | 「従来」「今のところ何でもない」領域の下地 | — |
| ニュートラルの枠線 | `#cfd6dc` | 区切り線・淡い枠・補助の矢印 | — |
| 弱い要素 | `#9aa4ad` | 意図的に「無い・過去・弱い」を表す線や形。文字には使わない（2.5:1） | — |

役割の割り当ては図の主張で決める。既定は次のとおりで、1本の記事の中では割り当てを変えない。

- 主強調は、図が「これが大事」と指す側（残る側・基盤・新しい像）
- 第2強調は、主役と対比される相手（AI 側／人間側、外から来るもの）。対比が無い図では使わない
- ニュートラルは、比較の基準になる「従来」「今まで」の側
- 「弱い要素」は、無い・消える・過去を表す時だけ。文字には使わず、形と線に限る

悪い例: 図1で基盤を青緑、図2で同じ基盤を紺、図3で橙にする（読者は同じものと気づけない）。
良い例: 3枚とも基盤は「濃色の面」の帯で、副題の語も同じ。

## 文字

- 書体は同梱の Zen Kaku Gothic New。見出しと主役のラベルは Bold、それ以外は Regular
- 文字色は墨が既定。塗りの上は白。色文字は「文字用」の HEX を使い、塗り用の HEX を文字に流用しない
- 英字の固有名詞（Tableau／MCP／API 等）は本文の表記に合わせ、図の中で略さない

階層は3段。既定値から下げない。上げるのは主役を目立たせる時だけ（見出し 32〜40px まで）。

| 用途 | 既定（1180 幅） | 下限（1180 幅） | 本文幅 720 換算の下限 |
|---|---|---|---|
| 見出し・句（図の主張を担う語） | 26px | 24px | 14.4px |
| 主ラベル（要素名・軸名） | 22px | 22px | 13.2px |
| 補助ラベル・注記・出典 | 18px | 18px | 10.8px |

18px 未満は 0.6 倍で 11px を切り、本文幅では読めない。「小さく添える」表現は、サイズを下げる代わりに色を補助の下限まで落とすか、位置を端に寄せて実現する。

## 文字色のコントラスト

背景に対する WCAG のコントラスト比で、次の下限を守る。

| 用途 | 下限 |
|---|---|
| 読ませる文字（見出し・主ラベル） | 7:1 以上 |
| 補助文字（注記・軸目盛・出典） | 4.5:1 以上 |
| 意図的に「無い・弱い・過去」を表す文字 | 3:1 以上 |

- 淡色化は上の下限までに留める。3:1 を切る文字は「弱い」ではなく「消えている」
- 背景 `#fbfbfa` の上では、`#8a949f` 系のグレーは 3:1 前後で補助文字にも足りない。補助文字は配色表の `#5c6670`（5.7:1）を使う
- 塗りの上に置く文字は、その塗り色に対して比を取る
- 検算は WCAG のコントラスト比（相対輝度の比）で行う。手計算が面倒でも、明度の近い既知の組み合わせで代替せず、実際に比を出す

## 図中のタイトル

図のタイトルは、図が示す対象を短い名詞句で言うだけにする。主張は本文とキャプションに任せる。

- 良い例: 「工程の分担」「Tableau MCP の構成」
- 避ける例: 「Claude Code が担当した工程と、人に残ったこと」（2句の並列）、「見せ方の合意はHTMLで、共有はBIプラットフォームで」（対句）
- 本文の見出しと同じく、コロンの「主題：要約」・対句・「〜ではなく〜」を使わない。型の説明と出典は [voice-style.md](../../article/references/voice-style.md) のルール 17 にある
- 副題を置く時も、図の中の語の並びを言うだけにし、結論を書かない

## キャンバスと縦横比

- 幅 1180 を基準にする。高さは 660〜885（16:9〜4:3）。幅を変える時は文字サイズも比例させる
- 縦横比は 16:9〜4:3 に収める。縦長にする時は 3:4 まで。スクロールを要する図は 2 枚に分ける
- 横長の時系列・段階列（例 1240×336 のような 4:1 弱）は本文幅で文字が潰れる。行を折り返すか、縦積みにする
- 外周の余白は 48px 以上。要素の群と群の間は 32px 以上
- 背景は塗る（透明にしない）。ブログ側の背景色に依存させないため

## 線と形

- 角丸は 10px。囲みは1種類の角丸で統一する
- 線幅は主役 2px、補助 1.5px。矢印は1種類（先端を三角で閉じる）
- 破線は「無い・弱い・仮」の意味にだけ使う。装飾で破線にしない
- 人物アイコンは頭（円）＋肩（半円）の1形で統一し、濃淡で属性を表す。表情や服装は描かない
- 影・グラデーションは使わない。奥行きは色の濃淡と重なりで出す

## 繰り返し出る要素

同じ記事の複数の図に同じものが出る時は、色・形・位置の癖・ラベルの語を揃える。

- 語は本文の初出の語をそのまま使う（本文が「信頼できる基盤」なら、副題も本文の並び「セマンティクス・コンテキスト・データ」）
- 前の図で「帯」だったものを次の図で「箱」にしない
- 1枚目で決めた割り当て（例: 主強調＝Tableau 側、第2強調＝AI 側）を、記事内の残りの図に引き継ぐ。記事の途中で割り当てを変える必要が出たら、全部の図を直す

## 検算と最終確認

自己レビューに組み込む。

- 色は表の HEX をそのまま使う。近い色を目分量で作らない
- タイトルが対象の名詞句になっているか。主張・対句・コロンが入っていたら、主張はキャプションへ移す
- 文字を置いた背景ごとに、上のコントラスト比を満たすことを確認する。表に無い組み合わせ（例: 淡色の上に色文字）は比を計算してから使う

最後に、PNG を 0.6 倍で見ても読めることを確認してから合格にする。方法はどちらか:

- 縮小した PNG を Read して目視する（例: 幅 720px の PNG を別途書き出す、または画像ビューアで 60% 表示）
- viewBox を 720 幅換算で検算する。`font-size × 720 / viewBox幅` が「文字」の表の 720 換算の下限以上か

原寸の PNG が読めても合格にしない。原寸で読める図が本文幅で読めなくなるのが典型の失敗パターン。
