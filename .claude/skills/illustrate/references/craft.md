# Craft（構図の選択と仕上がりの採点）

## 作図前：構図を選ぶ

### 使い方

作図の前に「この図で見せたい関係は何か」を **1つ** に絞る。複数の関係を1枚に詰めると論点がぼやける。絞った関係を下表で引き、推奨視覚形を採る。**「とりあえず四角を矢印で繋ぐ」は最後の手段**（プロセス/依存以外では情報量が出ない）。

### 関係タイプ→視覚形の対応表

| 見せたい関係 | 推奨視覚形 | 避けたい既定形 |
|---|---|---|
| プロセス・順序（A→B→C） | 横/縦のステップ列。各ステップに状態変化を1語添える | 等間隔の箱を矢印で繋ぐだけ（変化が読めない） |
| 一対多・分岐（1つから複数へ） | fan-out（中心ノードから放射）。枝の太さ/数で量を示す | 縦に箇条書きを並べる |
| 多対一・集約（複数が1つへ） | convergence（複数の流れが1点に収束） | 矢印を全部同じ終点に向けるだけの密集図 |
| 対比・二項対立（X vs Y） | 左右2カラムを軸（境界線/対称構図）で割る。同じ行で属性を対置 | 2つの箱を並べるだけ（差分が視覚化されない） |
| トレードオフ・程度（多いほど○、少ないほど×） | 2軸の散布/象限、またはスライダー/天秤。位置で度合いを示す | 表だけ（数値の大小が直感に乗らない） |
| 階層・包含（大→中→小） | 入れ子（同心/包含矩形）または木構造。深さ＝階層 | フラットなインデント箇条書き |
| before / after（変化の前後） | 左右2状態を同一構図で並べ、変わった箇所だけ強調 | 2枚を無関係に並置 |
| 構成要素の分解（全体→部品） | 分解図（exploded view）。全体像から部品を引き出す | 部品名を列挙するだけ |
| 因果・連鎖（原因→結果が連なる） | 一方向の連鎖。分岐/合流があれば node で表現 | 双方向矢印を多用して因果方向を曖昧にする |
| 時間推移・経過 | timeline（時間軸を1本通す）。出来事を軸上に配置 | 箇条書きの日付リスト |
| 重なり・共通部分 | ベン図/重なる領域。交差に意味ラベル | 別々の円を離して置く |
| 位置づけ・地図（全体の中のどこか） | マップ/座標上に対象をプロット。周囲との相対位置で語る | 単独の箱に名前を書くだけ |

### 選定の原則

- **図形に意味を持たせる**：枠の大きさ・位置・距離・太さ・色の濃淡が、関係の何か（量・順序・近さ・強さ）を表しているか。何も表していない装飾枠は削る。
- **1枚＝1主張**：図のキャプションを1文で書けるか。書けないなら関係を絞り直すか、図を分ける。
- **テキストは最小**：図は文章の代替ではなく、文章で説明しにくい関係を担う。ラベルは語/短句に留め、文を流し込まない。
- 表に当てはまらない関係なら、上の原則に立ち返って構図を自作してよい（表は出発点であって制約ではない）。

## 描画後：Anti-Bland Rubric で採点する

判定は減点法だが、目標は減点回避ではなく **「飾った資料でなく、1枚の作品として成立しているか」**（雑誌の図版・ギャラリー作品の水準を北極星に置く。公式 canvas-design の "museum / magazine quality" 由来）。下の各項目は、その水準から外れる典型を潰すためのチェック。

### 採点手順

1. レンダリング済みの PNG を Read で開く（コードでなく**実際の見た目**を見る）。
2. 下の各項目を ✅/❌ で判定する。
3. ❌ が1つでもあれば作図に戻って直す。修正→再描画→再採点を繰り返す（**上限3周**）。
4. 3周しても残る ❌ は、サマリに「未解決」として正直に報告する（黙って合格にしない）。

### 採点項目

#### A. 伝達（最優先）
- [ ] **3秒で主張が読めるか**：パッと見て「何を言いたい図か」が掴めるか。掴めないなら情報過多か焦点不在。
- [ ] **図形が意味を担っているか**：枠・位置・距離・大小・太さが関係（量/順序/近さ/強さ）を表しているか。ただの飾り枠が並んでいないか。
- [ ] **キャプション1文で言い切れるか**：言い切れないなら関係を絞り直す。
- [ ] **ラベルが本文の語と一致しているか**：図だけの言い換えや、本文に無い評価軸（製品差・優劣）が入っていないか。

#### B. スカスカ・凡庸の回避
- [ ] **「箇条書きを2次元に置いただけ」になっていないか**：箱に語を入れて等間隔に並べただけ、は不合格。
- [ ] **プレゼンスライド然としていないか**：タイトル＋中央寄せ箇条書き、の定番レイアウトに陥っていないか。
- [ ] **視覚的な階層があるか**：主役・脇役・補足の区別が、大きさ/濃淡/配置で付いているか。全要素が同じ重みだと平坦。
- [ ] **「ボックス＆矢印」への安易な回帰でないか**：プロセス/依存以外でこの形なら、上の対応表で選び直す。

#### C. 仕上がり
- [ ] **余白が機能しているか**：詰め込みすぎ（窒息）でも、スカスカで間が持たない（散漫）でもない。要素を意味のあるまとまりに群化できているか。
- [ ] **整列が取れているか**：エッジ/中心が揃っているか。微妙にズレた要素は素人っぽさの主因。
- [ ] **テキスト量が適切か**：図に文章を流し込んでいないか。ラベルは語/短句。読ませる説明は本文側に置く。
- [ ] **文字サイズと色の下限を満たすか**：style.md の下限（1180 幅換算で主ラベル 22px・補助 18px、コントラスト 7:1／4.5:1／3:1、縦横比 16:9〜4:3）を満たし、0.6 倍で見ても読めるか。淡色化は下限の範囲内か。
- [ ] **共通の見た目に沿っているか**：style.md のパレット外の色や、同じ意味の要素に図ごとに違う色・語を当てていないか。影・グラデーションを使っていないか。
- [ ] **切り出しが正しいか**：要素が見切れていない／意図しない余白が大きすぎない。直すなら SVG の viewBox かルート要素（HTML は `#fig`）のサイズを要素に合わせて再実行する（撮影のクリップは `render-figure.sh` が行うので触らない）。
- [ ] **同梱フォントで描かれているか**：豆腐（□）やシステム既定フォントへのフォールバックに化けていないか。`document.fonts.ready` の status が全て `loaded` か（化けていたら base64 埋め込み手順を確認する）。

### 不合格時の典型処方

- 主張が読めない → 要素を削る。最重要の1関係以外を落とす。
- 平坦 → 主役を1.5〜2倍に、脇役を縮小・淡色化して階層を作る（縮小・淡色化は style.md の下限まで）。
- スライド然 → 中央寄せ箇条書きをやめ、上の対応表の関係特化の構図に置換。
- 窒息 → 余白を増やし、要素を2〜4群に群化。
- 見切れ/余白過多 → SVG の viewBox かルート要素（HTML は `#fig`）のサイズを合わせ直して再実行する。
