# 複数案モード

オーケストレータ（メイン文脈）が共通ブリーフを固定し、philosophy だけを変えた独立サブエージェント N 体に並列で描かせる。デザインの良し悪しは著者の主観が正なので、judge は人間。

## 大原則：分散は「仕込む」もの

同じ指示で N 体走らせると似た絵に収束する。各変種に**別々の philosophy（美学方針）**を割り当てて初めて分散が出る。

- **固定（全変種で同一）**：図にする主張、要素の意味対応（例: 脳＝X／手＝Y）、事実関係・固有名詞。
- **可変（変種ごとに変える）**：philosophy レンズ、medium、構図、比喩、配色、タイポ、余白の使い方。

可変の項目も style.md の既定の範囲内で変える。配色はパレットの中での割り当てと濃淡で変え、パレット外の色・影・グラデーションは使わない。

## 手順

進捗:

- [ ] **共通ブリーフを 1 つ書く**：SKILL.md「入力の確定」で決めた主張・見せたい関係・要素の意味対応・記事の事実をまとめる。これは全案で固定する内容
- [ ] **N と philosophy を割り当てる**：下の「philosophy レンズ集」から N 個選び、各案に 1 つ割り当てる（重複させない）。既定 N=3
- [ ] **N 体の独立サブエージェントを並列起動する**（general-purpose）。各エージェントに渡すもの:
  - 共通ブリーフ
  - 割当 philosophy
  - 変種インデックス k
  - 固有のセッション名 `ill{k}`
- [ ] **N 枚を著者に提示する**：各 PNG を届け、philosophy と狙いを 1 行で添える。**選定は著者**
- [ ] **（任意）統合**：著者が選んだ案を基に、他案の良い所を接いだ最終案をもう 1 枚作る

## philosophy レンズ集

変種ごとに1つ割り当てる。

| レンズ | 狙い | 典型の medium / 表現 |
|---|---|---|
| 技術構造図 | 正確さ・明快さ。エンジニアのホワイトボード | SVG。レーン/コンテナ境界、monospace アクセント、request/response ループ |
| 比喩イラスト | 親しみ・記憶に残る。概念を物として描く | SVG or HTML。象徴アイコン、温かい配色、手描き感 |
| 抽象幾何 | ポスター的・洗練。図形と余白と色で語る | SVG。最小要素、大胆な構図、限定パレット |
| ドメインメタファー | 概念を現実の場面に翻訳（盤面・調理場・機械・操り人形 等） | HTML or SVG。シーンを1枚絵にする |
| タイポグラフィック | 言葉そのものを主役に。型で意味を出す | HTML/CSS。大きな型、実フォント、最小の図 |
| フロー/シーケンス | 動き・順序・往復を見せる | SVG。矢印の流れ、段階、タイムライン |

レンズは出発点。当てはまらなければ SKILL.md「品質の原則」に従って独自の美学を立ててよい。

## 各サブエージェントへの指示

単一案モードの手順をそのまま実行させる。差分は 3 点:

- **philosophy を 3〜5 段落書く**（単一案は 1 段落）。命名した美学方針＝movement 名＋原則＋なぜこの概念に合うか。分散と完成度は厚い philosophy から生まれる（公式 canvas-design の design philosophy 流儀）
- 出力は `output/{記事}/images/src/variant_{kk}.svg`（または `.html`）と `output/{記事}/images/variant_{kk}.png`
- 戻り値は `{path, philosophy, 自己採点, 一言}`

## 並列実行の衝突回避

playwright-cli は同一セッションを並列で使うと壊れる。

- **固有セッション**：`render-figure.sh` の第 1 引数を `ill{k}` にする（作業 HTML もセッション名で分かれる）
- **自分のセッションだけ閉じる**：`playwright-cli -s=ill{k} close`。`close-all` は他案を巻き込むので使わない
- 作図ファイル名（`variant_{kk}.*`）が異なるので出力の衝突はない。worktree は不要
- 全案が終わった後、オーケストレータが `rm -rf .playwright-cli/` で一掃する
