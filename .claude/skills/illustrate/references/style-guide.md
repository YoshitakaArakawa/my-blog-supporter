# Style Guide（ブログ共通の見た目）

## 配色

パレットは次の表から選ぶ。表に無い色は使わない。1枚の図で使う有彩色は主強調＋第2強調の2色までで、残りはニュートラルで組む。

| 役割 | HEX | 使いどころ | 背景に対する比 |
|---|---|---|---|
| 背景 | `#fbfbfa` | キャンバス全面 | — |
| 墨（読ませる文字） | `#1b2430` | 見出し・主ラベル・塗りの無い場所の文字 | 15.1:1 |
| 補助文字 | `#5c6670` | 注記・副題・凡例・出典 | 5.7:1 |
| 主強調 | `#2f6f6b` | 主役の塗り・枠線・矢印。白文字を載せてよい（5.8:1） | 5.6:1 |
| 主強調（文字用） | `#215e5a` | 背景の上に主強調色で文字を置く時 | 7.2:1 |
| 主強調の淡色 | `#f1f6f5` | 主役側の領域の下地。上の文字は墨か補助文字 | — |
| 濃色の面 | `#26404a` | 基盤・土台など「支える側」の帯。白文字を載せる（11.0:1） | 10.6:1 |
| 第2強調 | `#b85a2a` | 主役と対になる相手の塗り・枠線。白文字を載せてよい（4.6:1） | 4.5:1 |
| 第2強調（文字用） | `#9c4a23` | 背景の上に第2強調色で文字を置く時 | 5.9:1 |
| 第2強調の淡色 | `#fdf3ea` | 相手側の領域の下地 | — |
| ニュートラルの面 | `#eaeef1` | 「従来」「今のところ何でもない」領域の下地 | — |
| ニュートラルの枠線 | `#cfd6dc` | 区切り線・淡い枠・補助の矢印 | — |
| 弱い要素 | `#9aa4ad` | 意図的に「無い・過去・弱い」を表す線や形。文字には使わない（2.5:1） | — |

役割の割り当ては図の主張で決める。既定は次のとおりで、1本の記事の中では割り当てを変えない。

- 主強調は、図が「これが大事」と指す側（残る側・基盤・新しい像）
- 第2強調は、主役と対比される相手（AI 側／人間側、外から来るもの）。対比が無い図では使わない
- ニュートラルは、比較の基準になる「従来」「今まで」の側
- 「弱い要素」は、無い・消える・過去を表す時だけ。文字には使わず、形と線に限る

悪い例: 図1で基盤を青緑、図2で同じ基盤を紺、図3で橙にする（読者は同じものと気づけない）。
良い例: 3枚とも基盤は「濃色の面」の帯で、副題の語も同じ。

## 文字

- 書体は同梱の Zen Kaku Gothic New。見出しと主役のラベルは Bold、それ以外は Regular
- 階層は3段。既定値はキャンバス幅 1180 換算で、見出し 26px／主ラベル 22px／補助 18px。下限は readability-floor.md のとおりで、既定値から下げない。上げるのは主役を目立たせる時だけ（見出し 32〜40px まで）
- 文字色は墨が既定。塗りの上は白。色文字は「文字用」の HEX を使い、塗り用の HEX を文字に流用しない
- 英字の固有名詞（Tableau／MCP／API 等）は本文の表記に合わせ、図の中で略さない

## 図に置かないもの（既定）

図は、必要な情報を簡潔に集中して見せる道具。次は既定で置かず、著者が求めた時だけ足す。

- 注釈・補足の小文字（「〜は使っていない」「〜の場合」のような条件。本質情報でなければ図に書かない）
- 副題
- 凡例（色の意味は要素のラベルで分かるように組む）
- モチーフ（鍵・電球・歯車のような比喩の絵）
- チャット風の吹き出しの再現（会話の例は本文のコードブロックで示す）

1図1メッセージ。キャプションを1文で書けない図は、関係を絞り直すか分ける（構図の選び方は visual-rhetoric.md）。

意味の無い軸を持たせない。段の幅を次第に狭める（ファネル）・箱の大きさを変える・左右の位置をずらす、といった形の差は、量や順序を表す時だけ使う。表すものが無ければ同じ幅・同じ大きさのブロックで並べる。

同じ記事の既存の図やアーティファクトを下敷きにしない。前の図の構図は悪いアンカーになりやすく、本文の該当段落から図を起こす。本文の語を変えたら図も同名上書きで追随させる（「繰り返し出る要素」）。

## 図中のタイトルとキャプション

図中のタイトルとキャプションは役割が違う。

- **図中のタイトル**: 図が示す対象を短い名詞句で言うだけ。主張・要約・対句を入れない。良い例: 「工程の分担」「Tableau MCP の構成」。避ける例: 「Claude Code が担当した工程と、人に残ったこと」（2句の並列）、「見せ方の合意はHTMLで、共有はBIプラットフォームで」（対句）。見出しの型の考え方は [voice-style.md](../../article/references/voice-style.md) のルール 17
- **キャプション**（本文側の `![キャプション](images/…)`）: 著者の声で書いてよい。感情・但し書き・評価語が入る（「力技で作られるワークブック（辛い）」「作成と検証のループもAIに任せる（最初にやればよかった）」）。名詞句の規範をキャプションに当てない。AI が書く時は主張を1文で書き、著者が推敲で声を足す

## 図を提案する箇所

本文の自己レビューで「文章だけでは問題の構造が伝わりにくい」と感じた箇所には、図を提案する。問題の構造（何がどう困るか）・before/after・会話の流れの例は、図にすると伝わりやすい。事実の羅列や余談には置かない。

## キャンバス

- 幅 1180 を基準にする。高さは 660〜885（16:9〜4:3）。幅を変える時は文字サイズも比例させる
- 外周の余白は 48px 以上。要素の群と群の間は 32px 以上
- 背景は塗る（透明にしない）。ブログ側の背景色に依存させないため

## 線と形

- 角丸は 10px。囲みは1種類の角丸で統一する
- 線幅は主役 2px、補助 1.5px。矢印は1種類（先端を三角で閉じる）
- 破線は「無い・弱い・仮」の意味にだけ使う。装飾で破線にしない
- 人物アイコンは頭（円）＋肩（半円）の1形で統一し、濃淡で属性を表す。表情や服装は描かない
- 影・グラデーションは使わない。奥行きは色の濃淡と重なりで出す

## 繰り返し出る要素

同じ記事の複数の図に同じものが出る時は、色・形・位置の癖・ラベルの語を揃える。

- 語は本文の初出の語をそのまま使う（本文が「信頼できる基盤」なら、図のラベルも本文の並び「セマンティクス・コンテキスト・データ」）。主体の呼び方（製品名か「生成AI」か）は core.md の「語の取り決め」に従う
- 前の図で「帯」だったものを次の図で「箱」にしない
- 1枚目で決めた割り当て（例: 主強調＝Tableau 側、第2強調＝AI 側）を、記事内の残りの図に引き継ぐ。記事の途中で割り当てを変える必要が出たら、全部の図を直す

## 検算

- 色は表の HEX をそのまま使う。近い色を目分量で作らない
- タイトルが対象の名詞句になっているか。主張・対句が入っていたら、主張はキャプションへ移す
- 注釈・副題・凡例・モチーフが残っていないか。残すなら著者が求めたものか
- 幅・大きさ・位置の差が何かを表しているか。表していなければ揃える
- 文字を置いた背景ごとに、readability-floor.md のコントラスト比を満たすことを確認する。表に無い組み合わせ（例: 淡色の上に色文字）は比を計算してから使う
